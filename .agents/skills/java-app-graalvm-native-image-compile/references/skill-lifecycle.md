# 这份技能自身的迭代方法

技能是**活文档**：在项目开工前建骨架，在每次失败的那一刻补条目，在目标达成时才成熟。
这一节规定「怎么补、怎么标、怎么升版本、怎么搬到别的项目」。

## 1. 为什么要先建，而不是做完再写

- 做完才写，等于用**记忆的残渣**重建过程：真正值钱的细节（报错原文、试错顺序、
  哪条是死路）已经丢了，剩下的都是「看起来对」的结论；
- 边做边写还有一个副作用：**它逼你把问题问清楚**。
  一条写不成「症状 → 根因 → 修法」的经验，往往说明还没定位到位；
- 顺序反过来（先写技能）还能当 checkpoint：每次构建失败时，
  技能就是「我们已经知道了什么、下一步试什么」的清单。

## 2. 状态标记：四档，只许向上

| 标记 | 含义 | 允许写进技能吗 |
|---|---|---|
| **推断** | 我认为应该这样（来自文档、他处经验、推理） | 可以，但必须显式标「推断 / 待验证」 |
| **已踩坑** | 我遇到了这个问题并解决了，来源可指（哪次运行、哪条报错） | 可以，附来源 |
| **已验证** | 在目标平台上端到端跑通过（含真机运行） | 可以，作为结论使用 |
| **已定稿** | 在别的项目也复用过、或经过多轮迭代未变 | 可以，作为标杆使用 |

**只许向上，不许偷偷下移。** 工具链升级、平台变化、框架大版本更新时，
「已定稿」条目要**回到「已验证」重新确认**，而不是默认仍然成立。

## 3. 每次迭代要做的事（机械清单）

遇到失败时：

1. 在 SKILL.md 的**迭代日志**表里追加一行：日期 / 触发场景 / 结论（写到哪一节）/ 来源；
2. 在对应章节补条目，格式固定为 **症状 → 根因 → 修法**（三条各一句，不要写成散文）；
3. 若该条目推翻了旧条目，**改旧条目而不是叠加**（两套冲突的说法比没有说法更糟）；
4. 若参数清单变了：同步 `assets/native-image-args.txt`，并记一句「为什么」；
5. 若这是一条实验结论（性能、体积、JDK 差异）：写进
   [measurement-and-experiments](measurement-and-experiments.md) 的对比表；
6. 提升 `metadata.version`（见第 4 节）。

跑通一次完整流程后（例如终于编出来并能双击运行）：

7. 把「验证状态」表里对应的行从「推断」升到「已验证」，未验证条目逐条处理：
   要么补验证，要么降级为「实验位」并写明为什么不验。

## 4. 版本策略

| 版本 | 含义 |
|---|---|
| `0.x.y` | **试验中**：含未验证条目，或目标平台尚未端到端跑通 |
| `1.0.0` | **成熟**：满足 SKILL.md 里的四条达标判据（真机能跑、未验证条目清零、版本可追溯、**在别的项目复用过一次**） |
| `1.x.0` | 新增能力维度（例如新增平台、新增实验轴） |
| `1.x.y` | 修正条目、补充来源、澄清措辞 |

`metadata.maturity` 字段要跟版本一致：改版本时一起改，别让两者打架。

## 5. 把技能搬到别的项目（迁移顺序）

技能里必然混着两类东西：**通用的**（四类清单、隔离四条、自证四项）与
**AHA 特有的**（模块名、坐标、JavaFX 三件套、`AHA_HOME` 之类）。
搬的时候按这个顺序，能最快拿到可用的东西：

1. **先抄骨架**：`assets/module-pom.xml` + `assets/workflow-native.yml` 的替换位
   （SKILL.md 的「复用清单」列了要改的六处）；
2. **再抄参数起点**：`assets/native-image-args.txt`，然后按报错**重新试**四类清单 ——
   这一步不可能省，因为「哪些类必须运行期初始化」与依赖、框架版本强相关；
3. **跑通后回填**：把在新项目里新踩的坑补回技能（并标注来源项目），
   若某条推断在新项目被证伪，就在技能里改成「不成立 + 反例」——
   **被证伪的经验比成功的经验值钱**；
4. **最后决定要不要把技能里的项目专属条目参数化**：
   出现三个项目都用到的专属片段，才值得抽成模板；过早抽会得到一堆不用的占位符。

## 6. 反面模式（这些都是「看起来在维护技能」）

- **等到全部做完才写**：信息最全的时候不写，等细节烂掉；
- **把推断写成结论**：没有来源、没有验证状态的条目，会被下一个人当事实用；
- **只加不改**：新旧条目冲突时仍然两条都留，读者无从判断；
- **把项目专属内容写成通用规则**：`AHA_HOME` 之类别家的东西，
  冒充「通用做法」会误导；
- **技能与代码脱节**：代码里改了参数清单却不回写技能 ——
  所以本技能要求「先改技能、再改参数」；
- **只记结论不记症状**：下次遇到同样的报错，搜不到这条经验。
