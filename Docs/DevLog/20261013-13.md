## 🔧 先说一个流程事故（本批开工前发现并已处置）

批次 2 的 PR #138 **被合进了批次 1 的分支**（`feat/desktop-fxml`），**没有落到 `dev`**：

- #138 的 base 是 `feat/desktop-fxml`（我把批次 2 做成了 stacked PR）；
- #134 合并时**没有删除** `feat/desktop-fxml`，而 GitHub **只在 base 分支被删除时**才自动改 base；
- 于是 #138 合进了批次 1 的分支，`dev` 上至今没有 `provider-dialog.fxml`。

**这是我的设计导致的**，而且我先前明确预告过「#134 合并后 base 会自动变成 dev」——
**那句话是错的**。已开 PR [#139](https://github.com/ACANX/AHA/pull/139)（`feat/desktop-fxml` → `dev`）
把它补落到 dev；已核实两者差异**正好只有批次 2 的改动**（dev 上批次 1 是 squash 提交，
Git 按树比较，批次 1 的内容不产生差异）。

**口径修正**：除非有**真实的代码依赖**，各批次一律从 `dev` 拉分支；确实需要 stacked 时，
必须在 PR 描述里写明「base 合并后需要人/我手动 rebase 到 dev」，**不能指望 GitHub 自动改**。

> 本批确实有代码依赖：要复用批次 2 引入的 `FxmlViewChecks`，所以仍基于 `feat/desktop-fxml`。
> 等 #139 合并后我会把本分支 rebase 到 `dev`。
