### 2. 一键入口的取舍（为什么不做 PowerShell 重实现）

参考项目是 `UpdateNative.cmd` + `UpdateNative.ps1`（PowerShell 自包含）。本项目**不照抄**：

- 选件逻辑已经有 797 行成熟实现（多源发现 api→atom→page、断点续传、sha256、状态文件、
  `--list/--dry-run/--tag/--jdk/--backup`）——另写一份 PS 版 = 两套逻辑必然漂移（正是 TD-00015 反对的）；
- PS 版还有一个参考实现没解决的坑：`.ps1` 是 UTF-8 **无 BOM**，Windows PowerShell 5.1
  会按 ANSI 解码，中文提示变乱码（写 BOM 才行）——绕开它比修它省事；
- 于是 `.cmd` 只做三件事：定位仓库根、**依次探测 `py -3` / `python` / `python3`**（各自真跑
  `-c "import sys"`，避免 PATH 上存在但不可用的别名被误认）、调用对应薄壳并透传参数。

代价（如实写）：一键入口需要 Python 3，且必须在**仓库克隆内**运行（它调用仓库里的取件脚本）。
找不到 Python 时打印发布页地址——与「手动取件」同一条退路；速查里三种方式（一键 / 脚本 / 手动）都在。

### 4. 顺带发现：CLI 原生包 `--help` 崩溃的**根因**（转 issue #117）

```text
java.lang.InternalError: Can't load sun/text/resources/LineBreakIteratorData
  at picocli.CommandLine$Help$TextTable.putValue(CommandLine.java:17422)
```

桌面端原生参数里有 `-H:IncludeResources=sun/text/resources/LineBreakIteratorData`，
**CLI 侧没有** ⇒ 就是缺这一条资源。issue #117 早就开着、其「待排查方向 1」正是这个方向，
已把栈与根因补进去（修复本身不在本单范围）。

另：`run` 把 `${AHA_API_KEY}` 原样发出去**不是** bug——`AHA-Design-V1.md` §「未解析的环境变量
占位符保留原文，便于诊断」就是这么设计的（查过了才没误报）。

## 🩹 追加：Windows 真机双击失败 → 定位为 Python 的 OpenSSL 硬失败（2026-10-13 续）

ACANX 真机复测（就是 PR 里我请他们做的那一步）——**失败**，但失败得很有信息量：

```text
Using: py -3 Script\Python\DesktopNativeVersionUpdate.py
OPENSSL_Uplink(00007FFC93DDCB00,08): no OPENSSL_Applink
[FAILED] exit code 1 …
```

排查与结论（详见 `TS-2610-036`）：

1. **不是脚本逻辑**：引擎网络层只有最普通的 `urllib.request.urlopen`，没有自定义 TLS 配置
   （逐行核对，也未加载 CA 文件）；
2. **是 Windows 上 Python 的 OpenSSL 运行时坏了**：`no OPENSSL_Applink` 属 applink 机制的
   **硬失败**——打印一行后**直接终结进程**，所以**没有 traceback**（这也是最初的迷惑点）；
3. **对策只能是换执行路径**：新增 `--downloader auto|urllib|curl`；Windows 的 `auto` 先用
   **子进程**探一次 HTTPS（硬失败在进程内捕不到，只能靠子进程看退出码），不可用就改用
   系统 `curl.exe`（系统 TLS，不经过 Python 的 OpenSSL）；curl 路径同样支持续传；
4. 顺带修了一处误导文案：`.cmd` 失败时原来只列「网络不可达 / 限流 / 文件被占用」，
   与本次真实原因不符。

实测（本机 WSL）：curl 路径完整下载 41.2 MiB ⇒ 92.6 MiB 可执行文件、`version` 正常；
把包截断成 20 MB 当 `.part` 再跑 ⇒ `-C -` 续传补齐，`size` 与 `sha256` 校验均通过；
选择逻辑按「Windows + HTTPS 坏 → curl / Windows + 正常 → urllib / POSIX 不探测」逐项验过。

**待 ACANX 复测**：双击应看到一行「本机 Python 的 HTTPS 不可用…本轮改用系统 curl 下载」并成功。
另请顺手确认其 Python 的根因：`py -3 -V`、`py -3 -c "import ssl;print(ssl.OPENSSL_VERSION)"`、
`where libcrypto-3-x64.dll`。

## 🩹 追加二：Windows 侧改用 PowerShell 原生实现（2026-10-13 晚，按 ACANX 的要求）

ACANX 明确要求「在 Windows 中使用，参考 LegionFanControl 的 `Dist\UpdateNative.cmd` 实现」
——即**不要 Python 依赖**。这与上一节的定位一脉相承（病根就是本机 Python 的 OpenSSL），
但做法换了：不再在 Python 里兜底，而是**换实现**。

| 平台 | 入口 | 实现 |
|---|---|---|
| Windows | `Dist\Update*.cmd`（双击） | `Dist\UpdateNative.ps1`（.NET / Schannel TLS，**无需 Python**） |
| POSIX（WSL / Linux / macOS） | `python3 Script/Python/*NativeVersionUpdate.py` | 共享引擎（多源发现 / 断点续传 / sha256） |

照参考实现落的关键点（结合 AHA 的命名与已踩过的坑做了适配）：

- 不走 `/releases/latest`（原生包**全部**是预发行 ⇒ 会 404），改为按时间从新到旧扫、
  取第一个「真的带本平台资产」的 release；
- 资产匹配必须以 `-windows-amd64-jdk<JDK>.zip` 收尾并显式排除 `-Report.zip`
  （报告包与镜像包同版本号、只差结尾）；
- 下载前先探「exe 是否被占用」（运行中的 exe 覆盖/改名都会失败，别等 56 MB 下完才说）；
- 覆盖前旧版留 `.bak`；API 给了 digest 就校 sha256；状态文件防重复下载；
- **`.ps1` 存成 UTF-8 with BOM**：参考实现那份是无 BOM 的，PowerShell 5.1 会把中文提示读成
  乱码（顺手把这条固化成 `bin/CheckScripts.py` 的规则）。

顺手修了两个**真问题**（不是新功能，是守卫缺口）：

1. `bin/CheckScripts.py` 的 `SKIP_DIRS` 里有 `Dist` ⇒ **Dist 下这两个 `.cmd` 从来就没被检查过**
   （我上一轮说「由检查强制」是错的，已在 PR 里更正）；现改为用
   `git ls-files --cached --others --exclude-standard` 把 Dist 下的**手写入口**单独捡回来检查；
2. 两套实现必然漂移（TD-00015 的老问题）⇒ 新增断言：`UpdateNative.ps1` 的 `$kinds` 与
   `NativeVersionUpdate.py` 的 `KINDS` 的 tag 后缀 / 资产前缀 / 可执行文件名必须**逐字一致**。
   反向验证三项：改错一个字母 / 去掉 BOM / `.cmd` 里写中文——全部如期失败。

**未验证**：本机没有 Windows、也没有 `pwsh`，**PS1 从未实机执行过**（只做了「规则镜像验证」+
逐行复核 + 静态守卫）⇒ 需 ACANX 双击复测（预期一次到位；失败请把完整输出贴回）。
