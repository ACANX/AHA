# 开发日志 2026-10-20 23:00

> 关联：issue #403 —— 桌面端助手正文串段（开场白与总结被塞进同一个气泡）

## 🎯 问题

桌面端一轮对话的正文全部落在**同一条气泡**里：模型先说「先看看代码」、调用工具、
再给出总结，界面上却是「先看看代码看完了，结论是……」，总结凭空出现在工具卡片**之上**。

根因是事件契约缺了一层粒度：`DoneEvent` 只表示「整轮结束」，每轮出现一次；
而模型在一轮里会多次产出正文（工具调用前的开场白、工具结果回灌后的分析、收尾总结）。
视图拿不到段边界，只能把整轮正文往同一个 `Label` 里追加。

## 🔍 为什么把分段逻辑抽成 `AssistantSegments`

`DesktopShell` 是 JavaFX 类，本地没有图形环境就跑不起来（WSL 无 DISPLAY）。
把「段号 + 段内累积」这一层纯逻辑抽出来以后：

- 分段、幂等、跨线程累积都能在**无头**环境里直接断言（与 `FoldState`、`ApprovalText` 同一思路）；
- `DesktopShell` 只剩「按段号决定续写还是新建 `Label`」这一句真正的界面动作。

两处细节是踩过的坑，且都写进了单测：

| 细节 | 不这么做会怎样 |
|---|---|
| `end()` 必须**幂等** | 段边界后还会来一次 `DoneEvent` 收尾；不幂等会把同一段正文再渲染一遍，界面上多一条重复气泡 |
| 快照必须是**全文**而非增量 | 渲染侧按帧合并在途提交（`FxBridge`），增量会丢字 |
| 段号判据用「段号变了」而非「缓冲为空」 | 上一段恰好结束在空增量上时，两段会被并成一段 |
