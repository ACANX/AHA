## 📋 任务概述

#342 的七态状态位里，中断（ESC / Ctrl+C）直接调用 `idle()` 回到空闲，
状态行看不出「刚才是被中断的」，与正常完成、异常失败混在一起。
本次新增 **`INTERRUPTED`（已中断）** 状态，保留 2s 后回空闲。

## 🔧 技术要点

### 关键决策

- **中断是结束态而非空闲**：复用 `finish()` 的 2s 保留机制，保证与完成 / 失败一致；
- **审批中断单独回调**：`ConsoleToolApprover` 原来在 `finally` 里统一走 `onResolved`，
  会把中断误显示成「执行工具」；改为 `answer == null` 时走 `onCancelled`；
- **不显示原因**：中断是用户主动行为，不是错误，避免与 `FAILED` 混淆。

### 边界

- 中断态与失败态互斥：`failureSummary` 只在 `ErrorEvent` 设置，中断不会触发；
- 非 TTY（`StatusSurface.NONE`）仍整体关闭，不输出任何转义序列。
