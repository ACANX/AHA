## 📋 现象

#395 的 Ubuntu 原生桌面包（`SNAPSHOT:NativeDesktop`）在 WSL 里实测：

- GUI **能加载**了（#394 的 Pisces JNI 元数据修复生效）；
- 但**界面中文仍是方块**，#382 的修复看起来没起作用。

## 🔍 排查

### ① 环境确认：WSL 里确实没有中文字体

本机（WSL2 Ubuntu 26.04）：

```
$ fc-list :lang=zh | wc -l
0
$ fc-list | wc -l
89            # 全部是 Latin（DejaVu / Ubuntu）
```

### ② #382 只做了「探测 + 提示」，没有提供字体

`FontFallback` 的候选链（Noto / 文泉驿 / Droid …）全部来自 `Font.getFamilies()`；
系统一个都没有时 `family = null`，只打印安装提示——界面没有任何可用汉字字形，**当然还是方块**。
上一轮的验收标准写的是「提示可操作」，不是「汉字能显示」，这次把它补上。

### ③ 顺带发现：`MONOSPACE_CSS` 的逗号列表在 JavaFX 里无效

`FontFallback.MONOSPACE_CSS` 是一个逗号分隔的族名列表：

```
'Consolas', 'DejaVu Sans Mono', 'Noto Sans CJK SC', …, monospace
```

JavaFX 的 `-fx-font-family` 只接受**单个**族名（`<family-name> | <generic-family>`），
不会按列表回退；这个字符串会被当成一个不存在的族名，实际渲染回退到默认字体。
也就是说日志 / 工具输出等代码区的中文从来没有被 CJK 候选覆盖到。

### ④ native-image 不会自动包含字体文件

`aha-desktop-native/src/native/native-image-args.txt` 的 `-H:IncludeResources`
只列了 `png|jpg|…|bin` 等扩展名，**没有 `ttf|otf`**；即使把字体放进 resources，
原生包里也拿不到。

## ✅ 修复

| # | 改动 |
|---|---|
| 1 | 内置 `DroidSansFallbackFull.ttf`（`Droid Sans Fallback`，3.9 MB，Apache-2.0；`fc-query` 确认 `lang` 含 `cmn`），放 `aha-desktop/src/main/resources/fonts/`，附 `LICENSE-DroidSansFallback.txt` + `LICENSE-APACHE-2.0.txt` |
| 2 | `FontFallback` 新增 `BUNDLED_RESOURCE` / `bundledFamily()`：用 `Font.loadFont` 从 classpath 注册（懒加载、失败只试一次） |
| 3 | `resolve(os, installed, bundled)`：**系统 CJK 族 > 内置兜底**；非 Linux 一律不替换（外观无回归） |
| 4 | `monospaceCss()`：选中 CJK 族时返回**单一**族名（代码区汉字可读）；没有 CJK 族时退回原 `MONOSPACE_CSS`（行为不变）；4 处调用点同步 |
| 5 | `native-image-args.txt` / `native-image-args-jdk27.txt`：`-H:IncludeResources` 补 `ttf|otf` |
| 6 | 单测：内置兜底、系统优先、非 Linux 忽略内置、`monospaceCss` 单族名、资源存在性 |
| 7 | `README.md`：安装系统字体从「必须」改为「可选（更好字形）」 |
