# 开发日志 2026-10-15 16:00

> 关联 Issue：issue [#229](https://github.com/ACANX/AHA/issues/229)（切主题后输入框轮廓线丢失，纯色界面下分不出范围）
> 关联记录：`TS-2610-046`（本轮新建）、`TS-2610-029`（modena CSS 函数失效 ⇒ 整条声明被丢弃）、`TS-2610-028`（颜色落到属性 API）
> 关联提交：分支 `fix/issue-229-input-outline`

## 1 任务概述

ACANX 报：**切换主题模式后，对话输入框的轮廓线样式丢失，纯色界面下肉眼无法分辨输入框的位置范围**。
随即补充了一条关键信息：**这个问题（以及 #227）都只出现在原生镜像编出的 `.exe` 里**。

## 2 排查（先看「轮廓线本来从哪来」）

| 步 | 动作 | 结论 |
|---|---|---|
| 1 | 读 `DesktopShell.wireComposer()` | 内联样式只给底色 / 文字色，**没有边框** |
| 2 | 找那圈线从哪来 | 补丁样式表 `.text-input, .text-area … { -fx-border-color: %BORDER% }` + modena 自己的边 |
| 3 | 读 `TS-2610-029` | 原生镜像下 **modena 的 `derive()` / `linear-gradient()` 让整条声明被丢弃** |
| 4 | 读 `TS-2610-028` 的修复链 | 该类问题的既定解法：**把颜色落到属性 API**（`ThemePaint`） |
| 5 | 查 `ThemePaint.apply` 覆盖面 | 只有文字色 / 背景色 —— **边框从来没同步过**（缺口就在这） |
| 6 | 合起来 | 原生下：modena 的边被丢弃 + 补丁表对 `TextArea` 不生效 + 内联样式没边框 + 底色与页底同色 ⇒ 整块融入背景 |

## 3 根因（确定）

**轮廓线此前完全依赖 CSS**，而原生镜像下 CSS 对输入类复合控件不可靠：
modena 那条边被整条丢弃，补丁样式表那条对 `TextArea` 落不到实处，
而属性 API 兜底只覆盖了背景与文字、**漏掉边框** —— 三个条件叠起来就是「看不见输入框范围」。

**为什么 JVM 正常**：JVM 下 modena 能正常解析，那圈线是它画的；原生下这层没了，补丁与 API 又都没接上。

## 4 修复

| 环节 | 改动 |
|---|---|
| `ThemePaint` | 新增 `paintBorder()`：读 `-fx-border-color`（+ 宽度 / 圆角，缺省 1 / 3）→ `Region.setBorder(...)`；`apply()` 在背景之后调用。约定：没写边框就不动现有边框，写 `transparent` / `none` 才清空 |
| 三处输入类控件 | 对话输入框、会话搜索框、日志面板文本域的内联样式补上轮廓线（值取自补丁样式表，JVM 下外观不变；日志面板顺带改用 `themedForever` 并显式给底色 / 文字） |
| 断言 | 冒烟测试读输入框**实际生效的** `Region.getBorder()`，断言颜色为 `Palette.BORDER` 且切主题后跟着换 |

## 6 教训

1. **「JVM 正常」不能推出「原生正常」**：两边处理 CSS 的机制不同，这类 bug 必须以原生包真机为准。
2. **兜底要按「外观要素」清点**：背景、文字都兜了，边框漏了 —— 下次补兜底先列清「这个控件靠哪几样东西被看见」。
3. ACANX 在两单里都补了「只出现在原生 exe」这个条件，**这条信息直接决定了修法**（只改 CSS 一定白改）。
