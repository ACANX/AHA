## 📋 任务概述

修 issue #60：原生桌面镜像里 `prism.verbose` 打印的 **OS 与 D3D 驱动信息全是零值**
（`Windows version 0.0 build 0`、`Driver null`、`ven_0000, dev_0000`、`Max Multisamples supported: 0`），
而**管线和设备创建是成功的**——静默，不报错。

issue 当时的假设是「注册表 / WMI / D3D 枚举在 closed-world 读不到」。**实际根因不是这个。**

## 🔍 根因：native 按名回写字段，而字段没登记

| # | 事实 | 依据 |
|---|---|---|
| 1 | 值的唯一来源是 **native 方法** `nGetDriverInformation(int, D3DDriverInformation)` | `javap -p -c com/sun/prism/d3d/D3DPipeline.class` |
| 2 | 它填的是 **Java 对象的公有字段**（`osMajorVersion` / `osBuildNumber` / `driverName` / `vendorID` / `psVersionMajor` / `maxSamples` …） | `javap -p com/sun/prism/d3d/D3DDriverInformation.class` |
| 3 | `prism_d3d.dll` **含这些字段名** ⇒ native 用 `GetFieldID` **按名**回写 | `grep -rla <字段名> --include=*.dll` → 全部命中 `prism_d3d.dll` |
| 4 | 该类及其字段在**两份元数据里都是 0 条** | `reachability-metadata.json` 0 / `jni-config.json` 0 |
| 5 | ⇒ 回写不发生、字段保持 Java 默认值（0 / null） | `getOsVersion()` 的拼接格式与日志**逐字吻合** |

**关键认知**：**类能被加载 ≠ 它的字段能被 native 访问**——两套登记。这是本条最该记住的一条，
也是它成为「静默失败」的原因（值全零，进程照跑、窗口照开）。

## ✅ 完成内容

### 1. 元数据（`jni-config.json`，85 → 86 条）

```json
{ "name": "com.sun.prism.d3d.D3DDriverInformation",
  "allDeclaredConstructors": true, "allDeclaredMethods": true, "allDeclaredFields": true }
```

与 #37 / #39 的处置口径完全一致（那些也是 native 按名访问成员）。

### 2. 测试守卫（`NativeImageMetadataTest`，15 → 16 条）

`jniConfigRegistersPrismD3dDriverInformationFields`：该条目必须存在且含 `allDeclaredFields`。

### 3. 工作流两道（`DesktopNative.yml`）

| 改动 | 作用 |
|---|---|
| 步骤 ⑧b 加 `require_jni "…D3DDriverInformation"` | 守住**生效中**的 jni 清单 |
| Windows GUI 冒烟加两条断言 | ①必须打印 `OS Information:`；②**不得**出现 `Windows version 0.0 build 0` |

**为什么这两条断言不空过**：改前该串**必然出现**（今天两条原生构建都验过）⇒ 改后消失即为真前/后对照；
另加第 ① 条是因为「若 `prism.verbose` 被关掉，第 ② 条会恒真」——两条一起才封闭。

## ⚠️ 边界（诚实说明）

1. **CI runner 是无真实 GPU 的虚拟机**：D3D **驱动名 / 厂商 ID / Pixel Shader / Max Multisamples**
   这几项**本来就可能为零**，不能拿「CI 上还是零」当没修好；**驱动那一组需真机对照**。
   CI 上能判别的是 **Windows 版本号**（与 GPU 无关）。
2. **⑧b 那份清单并不完备**：它按 openjfx native 源码扫 `FindClass` / `GetMethodID` / `GetFieldID` 得出，
   **整段漏了 `prism_d3d`**。同类审查应覆盖 `prism_d3d` / `prism_common` / `decora_sse`
   ⇒ 记为 `TS-2610-034` 的 **Q2**。
3. **与 #48 的关系**：修完本条即可**直接检验** #48 的那个候选解释（「驱动能力探测全空 ⇒ 走保守分支 ⇒
   字形偏细」）——若字体仍发虚，该候选**被排除**。
