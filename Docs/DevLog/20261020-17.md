# 开发日志 2026-10-20 17:00

> 关联：issue #391 —— 流式对话 HTTP 400：历史窗口截断后 tool 消息失去前置 tool_calls
> 关联记录：`MessageSanitizer`、`SqliteMemoryStore#loadHistory`、`AgentEngine#prepare`

## 📋 任务概述

CLI 会话在某一轮后**稳定复现** HTTP 400，之后整会话不可用：

```text
LlmException: 流式请求失败: HTTP 400
{"error":{"message":"Messages with role 'tool' must be a response to a preceding message with 'tool_calls'"}}
```

报错发生在 `streamChat` 的第一跳（没有任何 SSE 事件、没有降级重试），说明请求体本身非法。

## 🔍 根因

1. **主因**：`SqliteMemoryStore.loadHistory` 用 `ORDER BY gmt_create DESC LIMIT ?` 取最近
   `maxContextEntries` 条再翻回正序。切割边界落在 tool 消息上时，`assistant(tool_calls)`
   被截在窗口外、它的 tool 结果仍在窗口内 → 历史以 `role=tool` 开头。
   同一约束在 `ContextCompactor#boundary()` 已经处理过（压缩时不切断工具调用与结果），
   但 `loadHistory` 的窗口没有 —— 同一规则两处实现，漏了一处。
2. **次因**：过滤逻辑只挡住「tool 缺 `tool_call_id`」。`deserializeToolCalls` 解析失败返回空列表时，
   assistant 作为空残留被丢，其后的 tool 却照常保留，同样产出孤立 tool。
3. 中断路径（`#341`）反向缺口：assistant 带 N 个 tool_calls 落库，只有 M(<N) 个 tool 结果。

## ✅ 方案

新增 `aha-core/.../llm/protocol/MessageSanitizer`（纯函数、幂等）：

- tool 消息必须能配对到**它之前**的 `assistant.tool_calls`（按 id），否则丢弃；
- assistant 的 tool_calls 中未被任何 tool 消息回应的调用被剔除；
  - 一条不剩时：有正文 ⇒ 退化为纯文本 assistant；无正文 ⇒ 整条丢弃；
- user / system 视为协议边界，越过边界后不再认领前面的 tool 消息。

接入两处（覆盖所有「历史 → 请求体」路径）：

- `SqliteMemoryStore#loadHistory` 返回前清洗（AgentEngine / ContextCompactor / 快照回放共用）；
- `AgentEngine#prepare` 拼装完 system + history + user 后最终清洗一次（流式与非流式同源）。

`ContextCompactor#boundary()` 的边界前退保留（压缩时不切断仍更符合语义，sanitize 是最后防线）。
