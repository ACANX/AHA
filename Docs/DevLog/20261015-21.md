## 1 任务概述

ACANX 报：**从亮色切到暗色时，下拉列表里「亮色」那一项不可见，但也没完全隐藏**；
要求「要么完全不展示，要么禁止选择」。附了一张真机截图。

## 2 排查（先看截图，再读样式表）

| 步 | 动作 | 结论 |
|---|---|---|
| 1 | 下载并**看图** | 三个选项里，中间那行只有背景没有文字；按钮区显示「亮色」⇒ 空白行 = **当前值 = 被选中项** |
| 2 | 读 `Theme` 与 ComboBox 构造 | 只有 3 个常量、`setAll(Theme.values())`、转换器给中文名 ⇒ 列表里**没有空项** |
| 3 | 数截图里的行 | 按钮区（亮色）+ 弹出层三行（暗色 / 空白 / 跟随系统）⇒ 空白行确实是 `LIGHT` 那行 |
| 4 | 读两份补丁表 | 基面规则 `4 层 > 链 + .list-cell`（**5 个类**）设了 `-fx-background-color` |
| 5 | 找选中态 | `.list-cell:filled:selected`（**1 类 + 2 伪类**）设了强调色背景 —— 特异性**低于**基面 ⇒ 永远盖不上去 |
| 6 | 找文字色 | `.list-cell:filled:selected .text`（**4**）压得过 `.text`（1）⇒ 文字**确实是白的** |
| 7 | 合起来 | 亮色：基面 `#FFFFFF` + 白字 ⇒ **白底白字**；暗色只是「碰巧能辨」 |
| 8 | 问「为何别处没暴露」 | 会话列表 `SessionCell` 是**在 Java 里显式上色**的（`ThemePaint.themed`），不过 CSS |

## 3 根因（确定）

**CSS 特异性失衡**：同一行里，**背景**走弱规则（被基面压掉）、**文字**走强规则（生效）。
背景与文字来自两条不同特异性的规则，是这个 bug 的核心 —— 只看其中一条都会得出「样式写对了」。

顺带说明「为什么至今没被发现」：本仓库的列表单元格一直在 Java 里显式上色（`SessionCell`），
把样式表的特异性问题**掩盖**了；下拉列表是第一个颜色完全交给 CSS 的 `ListView`。

## 4 修复

| 环节 | 改动 |
|---|---|
| 两份主题模板 | 状态规则（hover / selected）**加上与基面完全相同的选择器前缀**（同特异性时后者胜）；弹出层再加一层 `.combo-box-popup > …`（6 个类）；原通用规则保留（按钮格等不在 virtual-flow 里的单元格仍用它） |
| 生成物 | `python3 bin/GenThemeCss.py`（色源仍在 `Palette.java`，两份 CSS 是派生产物） |
| 静态守卫 | `bin/CheckTheme.py` 第 8 项：每条「设背景色的基面规则」都要有**类路径完全相同**的状态规则 |
| 运行期断言 | `AhaDesktopSmokeTest#listSelectionSurfaceIsReadableInBothThemes`：读选中格**实际画出来的**背景色 + `.text` 填充色，断言是 `FOCUS_BORDER` / `ON_ACCENT` 且**不相同** |
