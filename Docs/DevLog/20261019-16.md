## 📋 任务概述

档位独立为 `Tier` 节点，补充模型能力字段（实际模型名 / 推理 / 输入模态 / 上下文窗口 /
最大输出 / 思考强度映射）；`Adapter` 改名 `ApiType`，`anthropic` 统一为
`anthropic-messages`；旧格式保持可读并自动迁移。

## 🔧 技术要点

### 关键决策

- **模型 ID 与模型名分离**：`Tier` 只引用 ID，请求时取 `Name`，同一模型可在多档复用，
  也方便对接中转站别名；
- **旧格式在读取层迁移**：不在各个调用方做兼容分支，`ConfigLoader.normalizeModelNode`
  统一处理，写盘自然落到新格式；
- **`ProviderConfig` 紧凑构造器兜底**：即使某条路径漏了归一化，`Models` 键为档位名时
  也会自动补 `Tier`，保持旧语义；
- **兼容构造保留**：单模型与「档位 → 模型名」两种旧构造仍可用，桌面端与测试无需大改。

### 风险与后续

- `ThinkingLevelMap` 已能存取，但**尚未下发到请求**（OpenAI 的 `reasoning_effort` /
  Anthropic 的 `thinking` 结构需在 adapter 层按供应商映射），随 #355 一起落地；
- 旧客户端只读 `Model` 时拿不到默认模型，需要在文档里提示回退 `Tier` / `Standard`。
