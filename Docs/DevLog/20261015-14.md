## 1 任务概述

`BuildJVMArtifacts.yml` 在 `push` 到 `dev` 时，`build-publish` **每次都被跳过** ⇒ dev 的 JVM 预发行包
（tag `V<版本>-aha-jvm`）从 **2026-10-14 06:52 起 4 天没发出去**（而 run 结论一直是 `success`）。
根因是 `if` 里对 `inputs.publish` 用了 `!= false` 的宽松比较 —— `push` 无 `inputs`，`null != false` 求值为 **false**。

## ✅ 完成内容

### 1. 把「要不要发布」的判断从 YAML 表达式挪进脚本（方案 B）

`.github/workflows/BuildJVMArtifacts.yml`：

- `build-version` 新增步骤「归一『要不要挂发布页』（publish）」：
  `publish="${INPUT_PUBLISH:-true}"` → `case` 归一到 `true` / `false` 字符串 → 写 `$GITHUB_OUTPUT`；
- `build-version.outputs` 增加 `publish`；
- `build-publish.if` 改为 `needs.build-version.outputs.publish == 'true'`。

### 2. 守卫：workflow 里不得对 `inputs.*` 做宽松布尔比较

剥掉注释后匹配 `inputs.<name> == / != true|false`，违规点名并给出替代写法。
（初版忘了剥注释，结果把**说明性注释里引用的反例**也当成违规 —— 已按仓库既有惯例改用 `line.split("#", 1)[0]`。）

### 3. 规范与记录

## 🔧 技术要点

### 关键决策

- **选方案 B（判断进脚本）而非方案 A（改表达式）**：`null` / `false` / `''` 的折算坑只会在 YAML 表达式里咬人；
  落到 shell 就是普通字符串比较，可读、可测、可被守卫。这也是仓库「判定逻辑不写进 YAML」的一贯做法；
- **顺带把 #179 的意图补齐**：#179 原话是「push / dispatch 默认仍发布，只有显式 false 才跳过」，
  而实现从未生效 —— 归一步骤现在让 push（默认 true）、dispatch（默认 'true'）、
  workflow_call（快照线传 `false`）三条路径都符合原意。

### 验证方式

- `python3 bin/CheckScripts.py` 退出码 0；`actionlint` 对 `BuildJVMArtifacts.yml` 无输出；
- **守卫反向验证**：把 `build-publish.if` 换回 `inputs.publish != false`（代码行，非注释）
  ⇒ `CheckScripts` 点名 `对 inputs 做了宽松布尔比较` 并退出码 1；还原后复绿；
- 行为真机确认（合并后）：push 到 dev 应真出 `V<版本>-aha-jvm`；快照线的 `build-publish` 应**仍 skipped**。
