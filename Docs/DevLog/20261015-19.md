  为了让命令留在 `/snapshot` 家族里，这三条工作流的守卫都加了

## 🔧 技术要点

- **`$GITHUB_OUTPUT` 里同一个键不要写两次**：原先我先写 `ok=false` 兜底、再写 `ok=true`，
  而重复键的优先级**没有明确规定**（可能「先写的赢」）⇒ 所有通过路径都可能白跑。
  改成「键不存在即不打标、只在通过路径写一次」。**这是本地排练抓到的**。
- **守卫也会写错**：第一次写「命令前缀在文件里出现过就算过」，反向测试立刻证明它有洞 ——
  把**触发守卫**里的命令换掉，工作流永不触发而守卫不报。改成只认 `if:` 那一块。
- **本地排练**（假 `gh` 顶掉 API）跑了 10 个用例：通过 3 例（含 `jdk27 +model`）、拒绝 7 例
  （版本非法 / 平台词非法 / 缺原因 / 快照不属于本 PR / tag 不存在 / 无写权限 / 外部贡献者）。
- **守卫反向注入** 6 例全部被拦下（context 改名、触发守卫命令被换 / 丢一个、permissions 被注释掉、
  文档多一个清单项、必测行 token 改成 1）。
