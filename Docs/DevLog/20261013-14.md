### 2. 自审时抓到一处**自己引入的回归**

原实现的 `row(...)` 会给左侧的「键」标签套 `Palette.MUTED`。我把节点搬进 fxml 时**漏了这一步**——
标签未显式套色，暗色主题下对比度不足（正是 issue #44 / #49 的老症状）。

发现方式：在写 `wireView` 时逐条比对「原方法里对每个节点做了什么」，而不是只搬结构。
处置：给键标签补 `fx:id` 并在 `wireView` 里统一套色（授权弹窗 2 个、设置面板 3 个）。

> 记一笔：**「搬迁」类改动最容易丢的就是这类「顺手设置的一次性样式」**，它们不在类型签名里、
> 编译期完全看不出来。批次 1–3 之所以没漏，是因为那几处的样式本来就集中在 `themed(...)` 里。

### 3. `FxmlViewChecks` 再加两条

| 新检查 | 挡什么 |
|---|---|
| **fxml 必须是良构 XML**（JDK 自带解析器，**不需要 JavaFX 工具包**，所以能进 CI） | 漏闭合标签 / 非法实体 / 重复属性——`FXMLLoader` 对格式的要求就是 XML 本身，这类错只在装载那一刻炸 |
| **扫元素前先剔掉 XML 注释** | 修一个**假阳性**：我在 `tool-list-dialog.fxml` 的注释里写了 `Supplier<List<ToolDescriptor>>`，其中 `<ToolDescriptor>` 被当成元素类型，报「缺 import」。注释不是元素 |

**为什么没加「headless 真正装载」的测试**：`Labeled` 的 CSS 元数据在类初始化时会取默认字体，
而取字体需要 JavaFX 工具包；CI 无显示设备（Xvfb 是另一个待拍板项），这个测试会在 CI 上失败。
所以本批的**运行期行为仍然只能靠真机对照**——这一点在 PR 描述里写清楚了。
