## 📋 任务概述

核验 issue #125 并处置：它认定本仓库 `reachability-metadata.json` 的 **`reflection` 段**缺
`WinGestureSupport` / `WinDnDClipboard`（而 `jni-config.json` 里有），导致 Windows 原生 exe
抛两条 `ClassNotFoundException`、手势与拖放静默失效。

**结果是一个反转**：缺口的**事实**成立，但**成因判断错了**——这两个类的查找**根本不在反射路径上**。

## 🔍 核验结论（四处证据）

| # | 证据 | 做法 | 结果 |
|---|---|---|---|
| 1 | 本仓库现状 | 数两份元数据 | 反射段 **0** 条 / `jni-config.json` **各 1** 条（与 issue 一致） |
| 2 | **Java 侧有没有按名查找** | 解 JavaFX 25 的 `-win` jar，`javap -p -c` 看 `WinWindow` / `WinApplication` | `Class.forName` **0 处命中** |
| 3 | 那谁在查？ | 全 jar 常量池扫描 | 只有自身、`WinClipboardDelegate`（`new`）与 **`glass.dll`** ⇒ **native 侧查找** |
| 4 | 本仓库真机跑过没有 | CI run `38389103313` 的 Windows 腿（`Start-Process` 真启动 exe 20 秒） | 冒烟 `通过`；stderr **315 B**，两条异常 **0 次** |

⇒ 这两个类属于 `FindClass` / `GetMethodID` 一族，**正确归宿就是 `jni-config.json`**；
而本仓库**自 issue #39 起**就把它们放在 `NativeImageMetadataTest.PLATFORM_JNI_INIT_CLASSES` 里并有断言守卫。

## ✅ 完成内容

### 1. 补登记两条（`reachability-metadata.json`，473 → 475）

理由**如实写成两条**（不是「修 bug」）：① 让这两个类**确定进镜像**、不依赖静态可达链
（`WinGestureSupport` 在 Java 侧**零引用**；`WinDnDClipboard` 只是被 `WinClipboardDelegate` `new` 出来才可达）；
② 对齐**姊妹工程按反射段生成清单**的口径——那里缺这两条，其真机上确认会抛异常。

### 2. 补三道守卫

| 守卫 | 位置 | 守什么 |
|---|---|---|
| `reachabilityMetadataRegistersWindowsGlassGestureAndDndTypes` | `NativeImageMetadataTest`（14 → **15** 条） | 反射段这两条仍在、且带 `allDeclared*` |
| `require_meta` ×2 | `DesktopNative.yml` 步骤 ⑧ | **生效中**的可达性元数据里有这两条（三平台腿都跑） |
| `require_jni` ×2 | `DesktopNative.yml` 步骤 ⑧b | **真正的查找清单** `jni-config.json` 里仍有这两条 |

> 步骤 ⑧b 原本已守 `WinWindow` / `WinView` / `MacWindow` / `EventLoop` / 字体结构体，
> **恰好漏了这两个**——守卫的洞被这次核验补上。
