## 🎯 问题

桌面端一轮对话的正文全部落在**同一条气泡**里：模型先说「先看看代码」、调用工具、
再给出总结，界面上却是「先看看代码看完了，结论是……」，总结凭空出现在工具卡片**之上**。

根因是事件契约缺了一层粒度：`DoneEvent` 只表示「整轮结束」，每轮出现一次；
而模型在一轮里会多次产出正文（工具调用前的开场白、工具结果回灌后的分析、收尾总结）。
视图拿不到段边界，只能把整轮正文往同一个 `Label` 里追加。

## 🔧 审查修复轮（PR #404 自查报告）

首版实现有三处「CI 看不见」的时序缺陷，审查后逐条修掉，并都补了能在无头环境跑的用例。

### P1-1 正文与段收尾走了两条通道（顺序靠运气）

首版里正文增量直达视图（`appendAssistant` 内部用 `FxBridge` 合流），段收尾却投递到
`ui` 队列。两条通道各自有序、合起来无序：推理线程投递完段边界就继续处理下一条增量，
而队列里的 `endAssistant` 可能还没执行——下一段的增量因此落进上一段、段号不推进，
界面直接退回 #403 修复前的样子。

修法：`endAssistant` 与 `appendAssistant` 同属「视图内部自行合流」，都由推理线程直接调用。
`ChatView` 接口把这条线程契约写进 javadoc，`ChatControllerTest` 用一个「只排队不执行」的
投递器验证「段边界先于下一段增量生效」。

### P1-2 传输异常路径漏发段边界

`ContentSegmentEndEvent` 原先写在 `streamChat` **返回之后**。用户中断是正常返回，能覆盖；
断网 / HTTP 非 2xx / 超时走异常，`streamChat` 抛出后段边界就漏了——桌面端留下一条
永远收不了尾的气泡（段号不推进、半段正文留在缓冲里），用户修好网络再发一条会续写到
失败前那条气泡上。

修法：把 `streamChat` 整段包进 `try/finally`，`finally` 里无条件发段边界，异常照常上抛。
`AgentEngineStreamTest` 补一条「脚本发完 content 后抛异常」的用例，断言事件序列是
`content → segment-end` 且异常仍以原样抛出；`ChatController` 的 `catch` 里也补了一次
兜底收尾（`AgentService` 是可替换实现，不保证每位都补）。

### P2-1 同帧两段时前一段整段不渲染

`FxBridge` 的策略是「只保留最新值」。旧实现提交的是整轮全文，合并安全；分段后每段是
独立全文，`pending` 被段 1 覆盖时段 0 从未进入渲染。触发条件是「段间没有慢操作」，
概率低但确实存在（空开场白紧跟正文、短工具调用）。

修法：新增 `AssistantFrameBuffer`——提交「自上次渲染以来的段列表」，同段号替换（快照本身
是全文）、跨段追加，渲染后按 `drop(generation, uptoSeq)` 摘掉已渲染部分，批次因此最多只有
一个未渲染的「进行中段」，不随对话增长。`FxBridge` 的类型参数随之变成
`List<AssistantSegments.Segment>`。

### P2-2 复位后上一会话的在途快照被当成新会话第一段

`clearConversation()` 把段号归零、`renderedSeq = -1`，之后 flush 到的旧 `Segment(seq=2, …)`
会「新建气泡」并通过可见性检查。旧实现写进的是已下线的 `Label`（不可见），
修复反而把「静默丢失」变成了「可见污染」。

修法：`Segment` 带 `generation`，`reset()` 时 `generation++`；渲染侧**现取**当前代际比对，
不一致就整条丢弃。同时给 `FxBridge` 加 `clear()`（丢弃在途值、桥保持可用）并在
`clearConversation()` 里调用，批次缓冲也一并清空。代际**不缓存到字段**：缓存值本身也得
同步复位，多一处状态就多一处漏复位的机会。

### P3 `end()` 空段也推进段号

段边界之后还有一次 `DoneEvent` 兜底收尾，模型直接调工具时开场白为空——两次空 `end()`
各自推进段号，`seq()` 与实际段数对不上（仅日志 / 测试可见）。改成「无正文不占段号」，
段号恒等于有正文的段数。仍保持幂等（连续调用第二次返回 `null`）。

## 🔍 为什么把分段逻辑抽成纯逻辑类

`DesktopShell` 是 JavaFX 类，本地没有图形环境就跑不起来（WSL 无 DISPLAY）。
把「段号 + 段内累积 + 批次合并」抽成 `AssistantSegments` / `AssistantFrameBuffer` 以后：

- 分段、幂等、跨线程累积、同帧多段、复位丢残留都能在**无头**环境里直接断言
  （与 `FoldState`、`ApprovalText` 同一思路）；
- `DesktopShell` 只剩「按段号决定续写还是新建 `Label`」这一句真正的界面动作。

几处踩过的坑，且都写进了单测：

| 细节 | 不这么做会怎样 |
|---|---|
| `end()` 必须**幂等** | 段边界后还会来一次 `DoneEvent` 收尾；不幂等会把同一段正文再渲染一遍，界面上多一条重复气泡 |
| 快照必须是**全文**而非增量 | 渲染侧按帧合并在途提交（`FxBridge`），增量会丢字 |
| 段号判据用「段号变了」而非「缓冲为空」 | 上一段恰好结束在空增量上时，两段会被并成一段 |
| 段收尾必须与正文**同源** | 两条通道各自有序、合起来无序，下一段的增量落进上一段（P1-1） |
| 桥投递**批次**而非单值 | 同帧内两段时前一段整段不渲染（P2-1） |
| 快照带**代际号** | 复位后在途旧段被当成新会话第一段，可见污染（P2-2） |
