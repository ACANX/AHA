# 开发日志 2026-10-20 15:00

> 关联：issue #384 —— CLI 超长 CJK 行触发 JLine WCWidth 越界，渲染崩溃被误判为回合失败
> 关联记录：`SafeAbovePrinter`、`AboveStream`、`ChatCommand#runTurn`、`JLineStatusSurface`

## 📋 任务概述

`0.1.5.00380` 的 CLI 在一次工具输出（`AhaUpdate.sh`，28 KB，注释块大量中文）后整轮被判失败：

```text
java.lang.IllegalArgumentException: offset is out of bounds: 76
  at sun.util.locale.provider.BreakIteratorProviderImpl$GraphemeBreakIterator.following
  at org.jline.utils.WCWidth.charCountForGraphemeClusterBreakIterator
  ... Display.update → Status.redraw → LineReaderImpl.printAbove
  ... AboveStream.emit → LineWrapper.newline → StreamRenderer.block
  ... ChatCommand.runTurn
```

用户看到的是「回合执行失败」+ 两份相同堆栈，已经流式输出到一半的内容丢失。

## 🔍 根因

- JLine 4.4.6 的 `WCWidth` 在 `Display` 跨行复用 `BreakIterator` / `CharSequenceCharacterIterator`
  时，会用越界的字符索引调 `BreakIterator.following`（实测 `76`）。触发内容是「长行 + CJK 全角」，
  但它是 **JLine / Display 内部**的索引不一致，不是我们喂进去的文本本身有错。
- 上游 4.4.8 的 `WCWidth` 与 4.4.6 **逐字相同**（下载两份 sources 比对），升级不能解决。
- AHA 侧把它当成业务失败：`AboveStream.emit` 不兜异常 → `ChatCommand#runTurn` 的
  `catch (RuntimeException)` 记 ERROR 并再打一份堆栈 → 回合终止。

## ✅ 方案

1. **渲染异常不升级为回合失败**（issue 建议的第 1 项，最高优先级）
   - 新增 `aha-cli/.../tty/SafeAbovePrinter`：包装 `LineReader#printAbove`
   - 首次 `RuntimeException` → 一条 WARN（只记一次）→ **永久降级为直写**：
     `suspend` → `terminal.writer().println` → `resume`
   - 降级后不再重试 `printAbove`：JLine 的缺陷每行都会复现，逐行重试只会刷日志
   - 只捕 `RuntimeException`：JLine 的 IAE / IOOBE 都在这一族；`Error`（OOM 等）继续上抛
2. **错误只打一次**（issue 建议的第 3 项）
   - `runTurn` 的 catch：完整堆栈进日志，终端只给 `[error] 摘要（完整堆栈见日志）`
   - 删除因此不再使用的 `stackTrace(Throwable)` 辅助方法
3. **回归用例**（issue 建议的第 4 项）
   - `SafeAbovePrinterTest`：正常路径、降级后不重试、suspend/resume 顺序、
     连降级都失败时不抛出、含 CJK 的长行经 `AboveStream` 不中断

## 🚫 本单未做

- **彻底替换 JLine 的宽度计算**（issue 建议的第 2 项）：现状 `LineWrapper` + `TextWidth` 已按显示宽度
  折行，越界发生在 JLine `Status`/`Display` 内部的 iterator 复用（我们传进去的每行并不超宽），
  在不替换 `printAbove` / `Status` 的前提下无法根治；而替换会牵动「输入行常驻底部」的整体交互。
  本次先保证「异常不中断回合」，根治方向另开单评估（自实现 printAbove 或等上游修复）。
- 状态区在降级后仍会显示，只是正文改走直写（`suspend/restore` 由 `SafeAbovePrinter` 包裹）。

## 🔧 验证

- `python3 bin/CheckChanged.py`：无需文档检查（本次只改 Java）
- 新增单测由 CI 的 `Build` 承担（本机不跑 Maven）：
  - 正常路径走 `printAbove`；
  - 抛 `IllegalArgumentException: offset is out of bounds` 后降级、且 `printAbove` 只被调一次；
  - suspend → write → resume 顺序；
  - 降级路径本身抛异常时不外泄；
  - 含 CJK 的长行经 `AboveStream` 不中断，且正常实例确实走 `printAbove`（反向对照）。
- **真机验收待 ACANX**：重复触发 `file-read` 大文件（注释块大量中文）后，回合应继续完成，
  日志出现一条 `printAbove 渲染失败（已降级为直写…）`。

## 📝 遗留

- 降级期间正文与输入行可能短暂错位（直写不经过 JLine 的行缓冲）——这是「不中断回合」的取舍；
- 若上游修复 `WCWidth` 的 iterator 复用问题，可移除降级路径，恢复单一 `printAbove` 通道。
