## 1 任务概述

PR #206 上出现两条快照评论，在「两条线都没打标签」的窗口里**除 marker 外逐字相同**，
而 marker 是不可见的 HTML 注释 ⇒ 读者分不清哪条是 JVM 线的、哪条是原生线的。
按 ACANX 的要求（要么有差异、要么合成一条），本轮修成「**可辨识 + 同刻只一条**」。

## ✅ 完成内容

### 1. 评论标题带「线 · 本线目标范围」

`.github/Python/SnapshotPlan.py` 新增 `line_label()`，`notice_body()` / `comment_body()` 的标题统一启用：

| 线 | 标题 |
|---|---|
| JVM | `### 快照包（JVM 线 · Desktop-JVM / Cli-JVM）：本次未出包` / `：`<版本>`` |
| 原生 | `### 快照包（原生线 · <本工作流目标>）：本次未出包` / `：`<版本>`` |

`out()` 同步增记 `native_target`，供原生线标题写出自己负责的目标（`Desktop-Native` / `Cli-Native`）。

### 2.「未打任何标签」时只由 JVM 线落一条评论

`decide()` 的 `elif not targets:` 分支改为 `owns_comment=(line == "jvm")` ——
否则 JVM 线 + 两条原生线会各写一条同义评论，正是要避免的情形（实测 PR #206：三条工作流都走这个分支）。

### 3. 自检与规范

- `--self-test` 增两条断言：「未打任何标签」时只由 JVM 线落评论；两条线标题各自标明线（现 **30 条**全绿）；
- `Docs/DevSpec/BuildSpec.md` §11.4 新增硬约定 + 变更日志 → v1.33.0。

## 🔧 技术要点

### 关键决策

- **选「有差异」而非「合成一条」**：合成一条需要两条线对同一评论做「读—改—写」，
  而它们是**各自独立的并发工作流**，互相覆盖正是 #165 实施期实测踩过的坑（共用 marker 会把对方的评论
  改写成「未出包」）。标出身份 + 同刻只一条，既满足要求，又不引入竞态；
- **「只由 JVM 线落评论」的归属选择**：JVM 线是唯一覆盖两个 JVM 目标的工作流，且「未打标签」时
  它的提示（`/snapshot` 用法）对读者最通用；原生线两条各自只管一个目标，且它们不发就不会重复。

### 验证方式

- `python3 .github/Python/SnapshotPlan.py --self-test`（30 条全绿，含新增 2 条）；
- 本地生成三种场景的评论正文预览（无标签 / 只原生标签 / 只 JVM 标签），确认标题可辨识；
- 四道静态检查 `CheckDocs` / `CheckSkills` / `CheckScripts` / `CheckTheme` 退出码 0。
