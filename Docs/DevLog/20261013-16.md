## 📋 任务概述

补齐**界面路径的自动化覆盖**。这是 FXML 化四批期间反复暴露、当时都靠真机兜底的那个缺口。

## 🔍 缺口长什么样（三段式）

| 层次 | 改动前的覆盖 | 缺口 |
|---|---|---|
| **fxml 自身写对没有**（import / 构造器登记 / `fx:id` ↔ 字段 / 路径存在） | ✅ 静态对账（`FxmlViewChecks` + `UiResourcesTest`），秒级、进 CI | 已闭环 |
| **界面在原生包里能不能装起来** | ✅ 原生 GUI 冒烟（正面断言） | ⚠️ 只在 `push: dev` 与手动 dispatch 时跑，**PR 上看不到** |
| **界面装起来之后的交互**（折叠三条路 / Enter 发送 / 工具卡片 / 会话列表） | ❌ 无 | `AhaDesktopSmokeTest` 写了 340 余行断言，却被 `@EnabledIfSystemProperty("aha.ui.tests")` 关着 |

真实漏过的例子（都记在 `TS-2610-032`）：漏 `<?import?>`、反射漏构造器、失败标记被当死代码删掉、
批次 4 搬迁时丢掉的键标签样式——**每一件都只有真机能发现**。

## ✅ 完成内容

### 措施一：CI 跑完整 GUI 测试（`Build.yml` 新增 `ui-smoke` 作业）

| 项 | 决定 | 理由 |
|---|---|---|
| 放哪 | **独立作业**，不塞进 `build` 腿 | 它要图形环境（`Platform.startup` + GTK），塞进去会污染「快速反馈」的定位 |
| 挡不挡合并 | **不挡**（作业级 `continue-on-error`） | `BuildSpec` §7：可选管线不得进必需检查；GUI 测试天然比单元测试抖（窗口时序、焦点、字体） |
| 怎么暴露真相 | 红叉 + Job Summary（含结论、最近一行统计、失败时的日志尾部 60 行） | 与原生工作流同一套路 |
| 环境 | `xvfb-run -a` + 装 `xvfb libgtk-3-0`（其余依赖尽力而为） | 包名随 Ubuntu 版本变（`libasound2` vs `libasound2t64`），装不上不算失败——真缺了会以 `UnsatisfiedLinkError` 暴露 |
| 失败保护 | `timeout-minutes: 25` | JavaFX toolkit 会起非守护线程，防套件没退出时吃掉整个 CI 配额 |
| 容易踩的坑 | 用 `-pl aha-desktop -am` | 只 `-pl` 它会在本地仓库里找不到 `aha-core` 等依赖 |

### 措施二：原生构建在 PR 上可见（`DesktopNative.yml` 加 `pull_request`）

| 项 | 决定 | 理由 |
|---|---|---|
| 触发 | `pull_request` + **路径过滤**（`aha-desktop/**`、`aha-desktop-native/**`、`pom.xml`、该工作流自身） | 每次 5 条腿约 10 分钟；不过滤会让每个文档 PR 都烧一遍 |
| **发布** | **PR 事件下不发布**（`native-publish` 的 `if` 增加 `github.event_name != 'pull_request'`） | 否则会在尚未合并时往发布页推预发行包、留下无人认领的 tag（PR 号版本号，合不入 dev 就成孤儿） |
| 产物可见性 | 各腿的 `upload-artifact` 照旧 | PR 页面底部可直接下载 |
| PR 号来源 | 版本号计算里新增 `EVENT_PR`（`github.event.pull_request.number`），优先于「按提交反查」 | 事件自带，更直接，不依赖 API 是否限流 |

## 🔎 首次真跑：一口气抓到 7 处「断言写好后从未通过」的问题

这正是这个作业存在的意义——**这套断言此前从未被执行过**，所以里面既有坏掉的取节点方式，
也有与设计相矛盾的期望。**全部属于断言侧，产品代码一行未改。**

| # | 问题 | 真因 | 修法 |
|---|---|---|---|
| 1 | **25 处 `lookup("#" + id)` 全部返回 `null`** | 节点 id 形如 `aha.status`（**带点**），而 CSS 选择器里 `.` 是**类选择器**——`#aha.status` 被解析成「id=aha **且** class=status」 | 新增 `byId(Scene/Parent, id)`：遍历场景图直接比 `getId()` |
| 2 | 「Enter 后消息数变大」**永远不成立** | **首条消息会移除空态（−1）+ 加入消息行（+1）**，children 总数不变 | 新增 `messageRows()`：只数「非空态」节点 |
| 3 | 对话框里 `getDialogPane().lookup("#" + ARGS_ID)` 漏改 | 同上「带点 id」问题；它是**跨行写法**，没被批量替换覆盖 | 改用 `byId(...)` |
| 4 | 拿**发送按钮**验「主题重刷」 | 发送按钮没有内联样式（外观由 CSS 补丁表的 `.button` 规则负责，`getStyle()` 本就是空串） | 改用**输入框**（走 `themed()` 上色） |
| 5 | 「宽度不能超出左栏」是**空过** | 只 `buildRoot()` 却从不放进已显示的 Scene ⇒ 布局不发生 ⇒ 宽度恒为 0 ⇒ `0 ≤ 220` 永远成立 | 给该 shell 开一个真实窗口再断言 |
| 6 | 状态探针断言**永远看不到那个值** | 状态标签会被 `setBusy(true)` 覆写成「生成中…（Esc 中断）」，而 CI 无供应商配置、流不结束 | 断言移到**发消息之前** |
| 7 | 「翻回草稿」失败 | UP 把文本换成 `/help` 后**候选弹层立刻弹出**，而弹层打开时 ↑/↓ 归弹层用（**设计行为**） | 改用一条普通内容进历史，别拿 `/help` 当历史项 |

> **第 5 与第 7 条最值得记**：
> * 第 5 条是「**看起来有断言、其实什么也没保证**」——空过的断言比没有断言更坏，因为它给人虚假的安全感；
> * 第 7 条是「**断言与设计的冲突**」，不是缺陷。判据是去读代码里的设计意图
>   （`DesktopShell` 那段事件过滤器的注释明写「候选弹层打开时，方向键与确认键归弹层用」）。
>   **测试跑不起来时先怀疑断言**，但两者都要拿设计意图来判，不能凭感觉。

## ⚠️ 边界（诚实说明）

| 项 | 说明 |
|---|---|
| `ui-smoke` 跑的是 **JVM 模式** | 原生包里的交互仍未自动化——那一段继续由原生冒烟与真机负责 |
| 它**不挡合并** | 若长期红着没人看，价值会退化。验证标准之一是「稳定跑一段时间后，再决定要不要升级成必需检查」 |
| 首次运行的库依赖不确定 | Xvfb/GTK 的可用性只能在 CI 上验证；若首轮失败，按报错补库（作业非阻塞，不会挡任何合并） |
| `pull_request` 下的原生构建消耗 | 每个相关 PR 多一次 5 腿构建；`concurrency` 会取消被覆盖的旧运行 |
