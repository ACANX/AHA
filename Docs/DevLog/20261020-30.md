## 关键决定

1. **折叠状态放在闭包里，不重建节点树**：主题切换只重跑 `styler` 的样式字符串，
   `FenceFold` 实例不动，因此「展开/收起在主题切换后保持」是结构上成立的，不是靠额外保存。
2. **图片占位用 `Hyperlink` 的 `graphic`**：加载成功后 `setGraphic(new ImageView(...))`，
   不去 `TextFlow` 里替换节点——替换需要父节点与下标，遇到表格单元格 / 列表项嵌套时容易错位。
3. **白名单在 `ImagePolicy` 里，不在渲染器里**：渲染器只管「点了之后怎么办」，
   判定本身可无头单测；`data:` / `http:` / 相对路径在点击前就不会产生 `Image` 实例。
4. **`file:` 放行是刻意取舍**：本机图片（截图、生成图）是桌面端最常见场景；
   代价是「恶意 Markdown 可指向本机文件」，但用户要主动点击才加载，且显示的是用户自己的文件。
