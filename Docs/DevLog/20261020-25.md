## 三个决定及理由

1. **样本放 `aha-core` 的 main 源码，不放测试资源**：Maven 的测试类不跨模块可见，
   放 test 里 CLI 与桌面端必然各复制一份——复制正是语义漂移的来源。
   代价是 core 多了一个 `MarkdownSemanticsSamples` 公开类，Javadoc 里已写明它只服务两端测试。

2. **`escape-literal` 三条标 `pending`**：`InlineScanner` 目前不处理反斜杠转义，
   若把它现在的行为写成期望，等于把「已知未实现」固化成正确（PR #404 审查 P3-2 的同类教训）。
   S1.2 实现转义后把 `pending` 置 `false` 即可启用。

3. **桌面端两条用例用反射 + `@Disabled`**：`MarkdownParser` 还不存在，直接引用会编译失败；
   反射让骨架能先合入、后启用（S1.1 解除时换成直接调用并断言 AST 类型）。
