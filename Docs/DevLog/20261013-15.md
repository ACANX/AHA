## ✅ 完成内容

### 1. 目录调整（`git mv`，10 个文件）

```
com/acanx/module/aha/desktop/view/
├── fxml/    7 个 .fxml

```

Java 类仍在 `view/`，**包名不变**。

### 2. 路径集中到 `UiResources`

原先 10 条路径散在 7 个控制器（各自一个 `FXML_VIEW` 常量）+ `ThemePaint`（两条 CSS）
+ `LogoImage`（一张图片）里。现在全部收到 `view/UiResources.java`：

- 常量是**绝对 classpath 路径**（以 `/` 开头），可直接交给 `Class#getResource`；
- `UiResources.relative(path)` 去掉前导 `/`，给 native-image 白名单对账用（那是 **jar 内路径**形式）。

**为什么用绝对路径而不是相对路径**：`getResource("x")` 相对**调用者所在的包**，
搬目录时最容易漏的就是这个语义差别；绝对路径不依赖「谁在调用」。

### 3. 新增 `UiResourcesTest`：补上静态对账拦不住的那一半

四个用例：

| 用例 | 挡什么 |
|---|---|
| `everyDeclaredResourceResolvesOnTheClasspath` | **真的去 classpath 取一次**每条路径——`getResource` 对写错的路径只返回 `null`，不抛异常、编译也过 |
| `everyDeclaredResourceIsWhitelistedForNativeImage` | 白名单命中（沿用 `FxmlViewChecks`） |
| `everyResourceSitsUnderItsOwnDirectory` | 新约定：每条路径必须落在 `fxml/` / `css/` / `image/` 之下 |
| `everyFxmlIsDeclaredHere` | 7 个骨架一个都不能漏进 `all()`（否则上面几条覆盖不到它） |

**关键认识**：资源白名单是**按扩展名**匹配的，所以「路径写错目录」在
`FxmlViewChecks.assertResourceWhitelisted` 里**照样通过**。真正能拦住它的是
「真去取一次」这条用例 + 真机点一遍。本用例不需要 JavaFX 工具包，所以能进 CI。
