### 2. 档位行：写死在 fxml，但用两条守卫防「口径分裂」

`ModelTier` 是 5 档（Ultra / Pro / Standard / Flash / Fallback），原来由
`for (ModelTier tier : ModelTier.strongestFirst())` 循环生成行。本批把 5 行**写进 fxml**
（整张表单一眼可读），代价是「枚举改了、fxml 忘了改」会静默少一两档。两道守卫：

| 守卫 | 位置 | 时机 |
|---|---|---|
| 数量硬校验 `setTierInputs` | `ProviderDialog` | 运行时（打开对话框即校验，不匹配直接抛，不静默少档） |
| `everyTierHasItsOwnInputRowInBothSections` | `ProviderDialogFxmlTest` | 编译后秒级（数量 + 命名 `editTier<configName>` + 标签文案三向对账） |

### 3. 把对账抽成可复用助手 `FxmlViewChecks`

批次 1 的 5 条对账写在 `DesktopShellFxmlTest` 里；本批要再用一次，于是抽成
`FxmlViewChecks`（不含 `@Test` 的静态方法），两个视图的测试类只提供「资源名 + 控制器类」，
再补自己特有的一条（主窗口：`id` 必须来自公开常量；供应商：档位口径）。

| 通用对账 | 挡住的错配（都真实踩过，见 `TS-2610-032`） |
|---|---|
| 元素类型必须已 `<?import?>` | 运行期 `LoadException: Xxx is not a valid type.` |
| 实例化类型必须登记 `allDeclaredConstructors` | 原生镜像 `MissingReflectionRegistrationError` |
| `fx:id` ↔ `@FXML` 字段（双向） | 注入静默失效（运行期 `null`）/ 死字段 |
| `.fxml` 命中资源白名单 + `Trampoline.class` 不被命中 | 构建全绿、启动即崩 |

**批次 3 / 4 直接复用这套**：新增一个视图 = 一个 `.fxml` + 一个约 60 行的测试类。
