## 1. 界面用法（Windows 现在就能用）

1. 打开「设置」（左下角 ⚙ 或菜单里），切到「**升级**」tab（也可以在「帮助 → 检查更新…」直接跳到它并自动检查一次）；
2. 选通道（默认 `Beta`）：
   - **稳定 Stable**：正式发布，长期保留 —— 当前还没有带资产的正式发版，列表会是空的；
   - **开发 Beta**（默认）：dev 分支最新合并产物，未做发布验收；
   - **快照 Alpha**：某个未合并 PR 的试包，**不是交付物**，7 天后会被清理（首次切换要确认一次）；
3. 点「**检查更新**」：列表按版本从新到旧（**按版本号排，不按发布时间**）；
   - 灰掉的行表示**这台机器用不了**（该版本没有你这个平台的包），鼠标停在上面会说明原因；
   - 空列表会说清是「该通道还没发过包 / 该平台形态没资产 / Alpha 已过期」中的哪一种；
4. 选中一行 → 底部按钮变成「升级到 X」/「降级到 X」→ 点它；
   - **降级要二次确认**，并且要勾选「我了解：`~/.aha` 里的配置与数据不会跟着回滚」；
5. 下载（有进度）→ 校验 → 程序会显示「正在替换并重启…」并**主动退出**；
   - 替换由外部 helper 完成（它要等你退出，因为运行中的文件换不掉），几十秒后程序会自己回来；
   - 期间**不要手工删 `~/.aha/update/`**。

升级完成后，窗口标题与「关于 AHA」里的版本号应当是目标版本。

## 2. 命令行入口（脚本化 / 界面点不下去时的兜底）

```bash
# 只检查：不下包、不换装
Dist/AhaDesktop.bat --update-to 0.1.3.00243 --check

# 暂存到 ~/.aha/update/ 并打印换装计划，但不拉起 helper（默认行为，防误触）
Dist/AhaDesktop.bat --update-to 0.1.3.00243

# 真换装（会拉起 helper 并要求你退出程序）
Dist/AhaDesktop.bat --update-to 0.1.3.00243 --yes
```

可选参数：`--channel stable|beta|alpha`、`--kind desktop-jvm|desktop-native|cli-jvm|cli-native`
（默认按当前运行形态推断）。参数写错会**明确报错**，不会静默用默认值（含 `--channel` 拼错）。

> **能力门在 CLI 上同样生效**（v1.2.1 起）：本平台没实现换装脚本（Linux / macOS），
> 或本安装形态没有可用的启动脚本（安装根里只剩一个单体 jar ⇒ 换完没人把程序拉回来），
> 换装类命令会**直接拒绝并返回非 0**，不会白下 55 MB。`--check` 不受限，随时可用。

## 3. 文件都在哪

| 路径 | 内容 |
|---|---|
| `~/.aha/update/<版本>/pkg.zip` | 下载到的包（未完成时是 `pkg.zip.part`；它只是排查现场，重试会**重新下载**，不做断点续传） |
| `~/.aha/update/<版本>/new/` | 解压出来的新包 |
| `~/.aha/update/backup/<旧版本>/` | 被替换下来的旧文件（含被新包删掉的文件），默认保留 2 份 |
| （清理规则） | **刚出炉的东西不删**：10 分钟以内动过的文件/目录（下载的包、解压副本、刚做的备份）一律留着，下次启动再清 —— 换装进行中再启动一次程序，也不会把正在用的文件删掉。所以升级完立刻看目录，可能还看得到 `pkg.zip`，**这是正常的** |
| `~/.aha/update/update-plan.json` | 换装计划（helper 的唯一入参；排障时最该看的就是它） |
| `~/.aha/update/update-result.json` | 换装回执（下次启动读一次就删掉，避免反复弹） |
| `~/.aha/update/helper-started` | helper 自报「我起来了」的标记（App 等它出现才退出）。正常结束后 Self-删；**升级完再看到它**说明上次换装可能还在进行或中途失败 |
| `~/.aha/update/helper-started` | helper 的「已启动」标记：helper 起来的第一件事就写它，App 等它出现才退出（等不到就留在前台报错，而不是「关了、什么都没发生」） |
| `~/.aha/update/update.log` | 追加式日志（检查 / 下载 / 解包 / 计划 / 回落结论） |
| `~/.aha/desktop.properties` | 设置（`Update.*` 键；**缺键取默认、不主动写盘**） |

## 4. 失败了怎么查

| 现象 | 先看 | 常见原因与处置 |
|---|---|---|
| 状态行说「限流」 | — | 发布页接口有频率限制（未认证 60 次/时/IP），**过一会儿再试**即可；不要连点 |
| 状态行说「该版本没有本平台可用的包」 | 报错里会列出该版本**实际有哪些资产** | 该平台那一腿没出（构建失败或还在上传）：换个版本，或等构建完成。程序**不会**偷偷退到更旧的版本 |
| 状态行说「本平台暂不支持应用内升级」 | — | Linux / macOS 本期不支持（[TD-00020](../TODO/TD-00020-PosixUpdateHelper.md)）：手动到发布页下 `aha-desktop-<版本>-<平台>.zip`，或用 `Dist/` 的同族脚本。**按钮会提前置灰**，不用等下完包才知道 |
| 状态行说「换装程序没有启动」 | `~/.aha/update/update.log` | helper 被拦下了（最常见是机器级 PowerShell 执行策略）。**安装目录没有被改动**，程序照常可用；可手动到发布页取件 |
| 升级完程序没自动回来 | `~/.aha/update/update-result.json` 的 `reason` | 计划里没有可用的拉起命令（少见：安装根里既没有启动脚本也没有原生 exe）⇒ 按 `reason` 的提示手动启动即可 |
| 升级后起来还是旧版本 | `update-result.json`、`update.log` | 换装失败并回滚了；`reason` 写在回执里，`update.log` 里有每一步的留痕 |
| 程序起不来了 | `~/.aha/update/backup/<旧版本>/` | 按目录结构把文件拷回安装根即可还原（helper 尝试过自动回滚，日志里有结论） |
| 提示「包里没有 AHA-PACKAGE.json」 | 包名 | 该包是 0.2 之前的旧包，没有包内清单 ⇒ 不能用来自我替换（用发布页的手工方式取件） |

### 3.1 每次启动时的自动收尾

程序启动时会顺手做三件事（都在后台虚拟线程里，失败只写日志，不影响使用）：

1. **读上次换装的回执**并告诉你结论（成功 / 失败 / 已回滚 / helper 没启动）——
   读完即消费，所以同一件事不会反复提示；
2. **清掉 `~/.aha/update/<版本>/`**（`pkg.zip` + 解包副本，每份 50–110 MB；含失败换装留下的那份），
   重试时会重新下载；
3. **按 `Update.BackupKeep` 裁剪旧备份**（默认保留 2 份）。

## 5. 平台支持范围（**别让它误导你**）

| 平台 | 检查更新 | 升级 / 降级 |
|---|---|---|
| Windows | ✅ | ✅（本期实现并验证） |
| Linux / macOS | ✅（只是读发布页） | **置灰** + 手动取件指引 |

「检查更新能不能用」与「包在不在发布范围」是**两个维度**：Linux x86_64 在发布页上**有**包
（`ubuntu-amd64`），但应用内升级的实现与验证本期只在 Windows 做；反过来 Windows ARM64
是**打不出包**（Maven Central 没有 `win-aarch64` 的 OpenJFX 分类器）。两种情况下界面给的指引不同。
