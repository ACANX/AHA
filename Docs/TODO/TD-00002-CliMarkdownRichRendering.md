## 现状

会话中模型输出的是原生 Markdown 文本，终端不做富文本渲染——没有颜色与格式区分。已有的若干渲染缺口被登记为「后续支持」：

| 项 | 现状 |
| --- | --- |
| 表格数据行之间的水平分割线 | 只有顶边 / 表头下 / 底边三条线，数据行之间为空 |
| 图片（Markdown 语法 `![alt]` + `(url)`） | 不渲染，保留字面量 |
| 语法高亮 | 围栏代码原样输出 |
| 链接的 OSC 8 超链接 | 不生成，只用「文本 + 弱化地址」 |
| 表格单元格内换行 | 不支持，单元格按单行处理 |

## 需求

- 在 Harness 侧识别 Markdown，并渲染为彩色 / 带格式的富文本（参考 pi / Claude Code）；
- 补齐上表中的渲染缺口（表格数据行分割线需先定「是否所有表格都加」）。

## 验收标准

- [ ] 模型输出的标题 / 列表 / 强调 / 行内代码 / 围栏代码 / 表格在终端有可辨识的格式区分；
- [ ] 表格数据行之间补水平分割线（或明确不补，并在 `PLAN.md` §7.1 记明取舍）；
- [ ] 重定向到文件时仍是纯文本，不出现断行的 ANSI 转义（与 `B-06` 同一约束）；
- [ ] 能力不足的终端（16 色 / conhost）自动降级，不花屏。
