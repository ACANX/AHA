## 现状

工具调用在终端的输出目前是平铺文本，缺少块状区分与差异展示；DeepSeek 供应商下工具调用的处理 API 也怀疑有缺失，可能在多轮循环的某一步失败后整条链路中断。

## 需求

- **编辑文件**：分块输出（对标 pi），并展示被改动处的前后差异；
- **添加文件**：分块展示路径与新增内容，内容超过 500 行时折叠；
- **浏览文件**：分块展示命令与文件内容，过长时折叠部分内容；
- **执行脚本 / 命令**：分块展示命令、执行结果或关键输出；
- **DeepSeek 工具调用**：补齐缺失的工具调用命令与处理 API，确保多轮循环不因某一步「无对应处理」而中断。

## 验收标准

- [ ] 编辑 / 添加 / 浏览 / 执行 四类工具调用在终端均按块展示，块边界可辨识；
- [ ] 编辑类调用能看到改动前后差异（新增行 / 删除行可区分）；
- [ ] 超长内容（> 500 行）折叠，并提示总量；折叠不改变实际回灌给模型的内容；
- [ ] DeepSeek 供应商下工具调用可完整走完多轮循环，无「调用缺失 API」导致的失败。

> 1. 工具调用的输出展示优化
>
> 支持对工具调用的输出展示做优化，比如：
>
> - 编辑文件
>   需要支持像 pi 那样分块输出编辑的命令，及对文件修改的部分的前后差异做展示；
> - 添加文件
>   则需要终端中分块展示文件的路径及添加的内容，
>   如果内容过长（超过 500 行），需要适当的做下折叠；
> - 浏览文件
>   需要终端中分块展示对应的命令及对应文件中的内容，
>   文件内容过长可以适当折叠下部分内容；
> - 执行脚本 / 命令
>   需要分块展示执行的命令及执行的结果或关键的输出；
> - 对于以 DeepSeek 大模型的工具调用中需要支持的调用相关的命令如果有缺失的，
>   需要补齐对应的工具处理 API，否则工具调用功能不完善，
>   可能导致循环调用中某一步骤调用失败使得工具无法继续执行下去，
>   需要补齐对应的工具调用的能力。
