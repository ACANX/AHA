1. 工具调用的输出展示优化
-------------------------

支持对工具调用的输出展示做优化，比如：

- 编辑文件
  需要支持像 pi 那样分块输出编辑的命令，及对文件修改的部分的前后差异做展示；
- 添加文件
  则需要终端中分块展示文件的路径及添加的内容，
  如果内容过长（超过 500 行），需要适当的做下折叠；
- 浏览文件
  需要终端中分块展示对应的命令及对应文件中的内容，
  文件内容过长可以适当折叠下部分内容；
- 执行脚本 / 命令
  需要分块展示执行的命令及执行的结果或关键的输出；
- 对于以 DeepSeek 大模型的工具调用中需要支持的调用相关的命令如果有缺失的，
  需要补齐对应的工具处理 API，否则工具调用功能不完善，
  可能导致循环调用中某一步骤调用失败使得工具无法继续执行下去，
  需要补齐对应的工具调用的能力。

2. Markdown 富文本渲染
-----------------------

对于工具调用完成后的会话任务完成后的总结发言，目前输出的是原生的 markdown 格式的文档文本，
但是在终端中不会被渲染成对应的富文本格式，需要 Harness 侧对这部分的文本做识别，
并格式化 / 美化其展示，就像 pi / claude code 中处理成彩色 / 多色带格式区分的富文本。

3. 输入框样式与 loading 动效
-----------------------------

对于终端界面中输入会话文本的那一行，后续不需要在行首位置加上 "aha>" 了，
只需要像 claude code / pi 那样在其上一行 / 下一行分别加上制表符，
将该行包裹成一个输入框就可以了，
如果能像 pi 那样能支持展示动态的 loading 旋转字符 / 加载的效果的话就更好了，
可以直观的告诉用户可以在此行输入对话的文本，下达后续的文本指令。

4. 状态栏信息
-------------

输入框下面要支持展示：

- 当前使用的模型及思考强度；
- 当前工作的目录；
- 此次会话任务上行消耗的 token，下行消耗的 token，总消耗的 token 数量，缓存命中率；
- 当前会话的当前的上下文占比，模型支持的最大的上下文长度；
- 当前 agent 运行的模式（自动模式，完全授权模式，严格模式）。

5. 斜杠命令
-----------

在输入的那一行，目前还不支持输入 / 开头的命令来完成相关的操作，比如：

- 多轮对话后，需要压缩上下文的话；
- 查看当前的设置；
- 切换模型；
- 调整模型的思考强度；
- 查看当前的 Harness 工具中的配置、上下文信息等。

需要支持在输入行中输入以 / 开头的命令来进入，
并且要支持下拉选项，可以方便用户快速选择需要使用的命令，
就像 pi / claude code 中支持的那样。

6. Windows 终端多行粘贴兼容性
-----------------------------

现在输入框中不支持复制带换行的长文本或者直接粘贴多行文本，
在 Windows 的终端中会报错，请解决这个兼容性问题。

[部分完成] 已做两项加固：
        1. 读取输入时的异常由「只捕获 Ctrl+C / Ctrl+D」改为宽幅兜底，
           任何读取失败都只忽略本次输入并继续对话，不再终止整个会话
           （此前粘贴触发的异常会冒泡到外层，直接结束对话——
           这可能就是「报错」的实际表现）；
        2. 显式启用 BRACKETED_PASTE，且 exit/quit 仅在「单行且无内嵌换行」时生效，
           避免粘贴一段含 exit 的文本意外退出。
        仍受限于终端能力：Windows Terminal 支持 bracketed paste，
        传统 conhost 不支持，此时多行粘贴仍会被逐行提交（Harness 侧无法改变）。

已知风险（同设计文档第 6.1 节）
-------------------------------

  R1 JavaFX + native-image 需要一长串运行期初始化清单，首次跑很可能在某个类上失败

  R5 产物体积大（几十 MB）；R6 未签名 → macOS Gatekeeper / Windows SmartScreen
  R7 「只在 Windows 试」可能掩盖平台差异
