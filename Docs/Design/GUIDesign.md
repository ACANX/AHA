## 1. 设计原则

| 原则 | 含义 | 反面 |
|---|---|---|
| **同一个大脑** | GUI 与 CLI 共用 `AgentService`，不重写 Agent 引擎、工具、记忆、权限 | 为 GUI 另写一套推理或工具调用循环 |
| **一屏能干活** | 打开即可对话，不做向导式多步配置 | 启动要连点 4 步才能说话 |
| **操作后果一眼可辨** | 沿用 CLI 的语义色：读取蓝 / 写入黄 / 执行橙 / 网络青 | 所有工具调用长得一样 |
| **危险操作必须当面确认** | 授权弹窗展示**将要发生什么**（参数、路径、命令），而不是只问「允许吗」 | 一个「允许」按钮配一句「该工具需要 WRITE 权限」 |
| **键盘优先** | 所有主流程都有快捷键；不依赖鼠标 | 只有右键菜单能到达的功能 |
| **失败要能读懂** | 错误给出「哪里错、怎么办」，不丢栈 | 弹窗显示 `java.lang.RuntimeException` |

### 三栏职责

| 区域 | 宽度 | 职责 | 可否折叠 |
|---|---|---|---|
| 左栏 | 220px | 导航（会话 / 记忆 / 工具 / 扩展 / 供应商 / 日志）+ 列表 | ✅ `Ctrl+B` + 栏边窄条按钮（鼠标） |
| 中栏 | 弹性 | 对话消息流 + 输入区 | ❌ 主体 |
| 右栏 | 280px | 本轮上下文：用量、工具调用、记忆命中 | ✅ `Ctrl+J` + 栏边窄条按钮（鼠标） |
| 底部 | 24px | 连接状态、模型、记忆开关、上下文占用、快捷键提示、版本 | ❌ |

**为什么右栏不塞更多东西**：它是「当前这一轮发生了什么」的镜子 —— 用量、工具、记忆命中。
会话列表、配置、日志都在左栏。右栏只在有内容时出现（空会话时隐藏，中栏因此变宽）。

## 3. 视觉语言

### 3.1 语义配色（与 CLI 一致）

CLI（256 色）与 GUI（十六进制）使用**同一套语义**，用户在两端看到同一种含义：

| 语义 | 用途 | CLI 色号 | GUI 十六进制 |
|---|---|---|---|
| 读取 | 查看文件、列目录 | `38;5;110` | `#87AFD7` 柔蓝 |
| 写入 | 修改 / 新建文件 | `38;5;179` | `#D7AF5F` 黄 |
| 执行 | 运行命令 / 脚本 | `38;5;209` | `#FF875F` 橙红 |
| 网络 | 发起请求 | `38;5;80`  | `#5FD7D7` 青 |
| 其它 | 未识别工具 | `38;5;250` | `#BCBCBC` 灰 |
| 成功 | 完成 | — | `#7FD37F` 绿 |
| 失败 | 错误、拒绝 | `38;5;224` on `48;5;52` | `#FF5F5F` 红 |
| 区块底 | 工具卡片底 | `48;5;236` | `#303030` 暗灰 |

**暗色优先**，亮色主题作为等价映射（同语义不同明度），跟随系统设置。
两个主题都必须保证正文对比度 ≥ 4.5:1。

### 3.2 排版

| 项 | 值 | 理由 |
|---|---|---|
| 界面字体 | 系统默认 UI 字体 | 各平台观感一致 |
| 代码字体 | 等宽（`Cascadia Mono` / `SF Mono` / `DejaVu Sans Mono` 回退链） | 工具参数、路径、命令必须对齐 |
| 正文 | 14px / 行高 1.6 | 长文可读 |
| 元信息 | 12px / 弱化色 | 不抢正文视线 |
| 间距基数 | 8px | 全部间距取 8 的倍数 |
| 圆角 | 卡片 6px，输入框 6px，按钮 4px | 克制 |

### 3.3 与 CLI 的一致性约定

| 项 | 约定 |
|---|---|
| 命令名 | `/compact` `/clear` `/model` `/memory` `/stats` 与 CLI **同名同义** |
| 工具卡片 | 结构对齐 CLI 的「区块」：首行（类型 + 工具名 + 目标）、结果行（状态 + 耗时 + 规模）、输出预览 |
| 记忆写入策略 | 同一开关 `Memory.ModelWrite: off\|candidate\|direct` |
| 权限语义 | 与 CLI 一致：本次允许 / 本会话内始终允许该权限 / 拒绝 |

用户在 CLI 学到的概念，在 GUI 里直接成立 —— 反之亦然。

## 4. 界面详解

### 4.1 对话消息流

消息**不用气泡**，用整宽文档流（与 pi / Claude 一致的观感）。区分方式是左侧竖条 + 标签：

```
   你
   │ 读一下 AgentEngine.java，看看工具循环的错误处理有什么问题

   助手
   │ 看了一遍。问题是第 8 次工具调用后只记录一条日志就继续往下走，
   │ 调用方拿到的是 `null` 而不是明确的失败原因。
   │
   │ 建议在 MAX_TOOL_ITERATIONS 处改为抛出 `ToolExecutionException`，
   │ 让上层能区分「模型放弃」与「工具失败」。
```

| 元素 | 处理 |
|---|---|
| 用户消息 | 左侧竖条 + 「你」标签，正文不折行渲染（原样） |
| 助手消息 | 左侧竖条 + 「助手」标签，正文渲染 Markdown |
| 时间戳 | 悬停显示，不常驻（常驻会变成噪音） |
| 代码块 | 等宽 + 深底 + **右上角复制按钮** |
| 表格 / 图片 / 链接 | 渲染为等价控件（表格可横向滚动） |

### 4.2 工具调用卡片

**这是桌面端最需要做好的组件** —— 一次会话里它出现得最频繁。

折叠态（默认）：

```
┌────────────────────────────────────────────────────────────────┐
│ ▸ 读取  file-read  AgentEngine.java          ✓ 完成 · 0.1s · 412 行 │
└────────────────────────────────────────────────────────────────┘
```

展开态：

```
┌────────────────────────────────────────────────────────────────┐
│ ▾ 读取  file-read  AgentEngine.java          ✓ 完成 · 0.1s · 412 行 │
│                                                                │
│   参数                                                          │
│   ┌──────────────────────────────────────────────────────────┐ │
│   │ path: src/main/java/…/core/agent/AgentEngine.java        │ │
│   └──────────────────────────────────────────────────────────┘ │
│                                                                │
│   输出（前 200 行，共 412 行）                    [ 复制 ] [全部] │
│   ┌──────────────────────────────────────────────────────────┐ │
│   │  1  package com.acanx.module.aha.core.agent;             │ │
│   │  2                                                        │ │
│   │  3  import …                                              │ │
│   └──────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘
```

失败态（整卡红边 + 红色结果行）：

```
┌────────────────────────────────────────────────────────────────┐
│ ▾ 执行  shell-exec  rm -rf build      ✗ 失败 · permission denied│
│   ┌──────────────────────────────────────────────────────────┐ │
│   │ command: rm -rf build                                     │ │
│   └──────────────────────────────────────────────────────────┘ │
│   [ 重试 ]  [ 修改参数后重试 ]                                   │
└────────────────────────────────────────────────────────────────┘
```

| 行为 | 说明 |
|---|---|
| 默认折叠 | 长输出不能淹没对话；用户需要时展开 |
| 首行颜色 | 按操作类型着色（语义见 3.1） |
| 耗时/规模 | 结果行右侧；不足 100ms 不显示耗时（与 CLI 同规则） |
| 复制 | 展开后提供「复制输出」「查看全部」 |
| 失败可重试 | 失败卡片直接给重试入口，不必重打一遍需求 |

### 4.3 输入区

```
┌────────────────────────────────────────────────────────────────┐
│  继续输入…                                                      │
│                                                                │
│                                                ↵ 发送   ⏹ 中断  │
└────────────────────────────────────────────────────────────────┘
  / 命令    @ 引用文件    Shift+Enter 换行    ↑ 历史
```

| 交互 | 行为 |
|---|---|
| `Enter` | 发送 |
| `Shift+Enter` | 换行 |
| `Esc` | 中断本轮（对应 CLI 的 Ctrl+C） |
| `↑` / `↓` | 历史输入（空输入时） |
| `/` | 弹出命令面板（同名于 CLI：`/compact` `/clear` `/model` …） |
| `@` | 弹出文件选择器，插入项目内相对路径 |
| 拖入文件 | 插入为 `@路径` |
| 多行粘贴 | 保留换行，不自动发送 |

发送后输入框**立即清空**，但保留在历史里 —— 生成期间可以继续输入下一条（与 CLI 的
「流式期间保持输入可用」一致），回车即排队。

### 4.4 授权弹窗（模态）

危险操作的**唯一**拦截点，必须说清「将要发生什么」：

```
┌─────────────────────────────────────────────────────────────────┐
│  需要授权                                                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   写入  file-write  src/main/java/…/AgentEngine.java            │
│                                                                 │
│   所需权限    WRITE                                             │
│   目标文件    src/main/java/com/acanx/module/aha/core/agent/     │
│               AgentEngine.java                                  │
│                                                                 │
│   变更预览                          ┌ 差异 ────────────────────┐ │
│   -  throw new IllegalStateException│  @@ -412,7 +412,9 @@    │ │
│   +  throw new ToolExecutionException│  - throw new Illegal…  │ │
│                                      │  + throw new ToolExec…  │ │
│                                      └─────────────────────────┘ │
│                                                                 │
│   本次会话内，file-read 已自动允许                                │
│                                                                 │
│              [ 拒绝 ]   [ 本次允许 ]   [ 本会话内始终允许 WRITE ] │
└─────────────────────────────────────────────────────────────────┘
```

| 设计点 | 理由 |
|---|---|
| 显示**差异预览**（写入类） | 「写入 AgentEngine.java」不足以判断风险，得看到改了什么 |
| 显示完整命令（执行类） | `rm -rf build` 与 `rm -rf /` 必须一眼可分 |
| 三个按钮语义与 CLI 的 y/n/a 一致 | 概念不因端而异 |
| 默认焦点在「拒绝」 | 回车不会误授权 |
| 记住范围是**权限**而非工具 | 与 CLI 的 `sessionAllowed.add(permission)` 一致 |
| `Esc` = 拒绝 | 与 CLI 的 Ctrl+C/Ctrl+D 视为拒绝一致 |

### 4.4.1 身份加载顺序（必须展示）

CLI 在启动信息里会列出身份文件的加载顺序（层级 + 路径 + 字符数）。**桌面端必须同样展示**：

- 位置：设置页「身份与记忆」一节；首次启动时可作为启动页的一角
- 内容：与 CLI 一致的顺序表，用户级在前、项目级在后，标注每份的字符数与「是否生效」
- 另外列出**未参与**的来源（配置内联兜底、内置身份）并说明原因

理由：顺序即优先级，看不到顺序就无法判断自己写的那份有没有生效——这是最容易被当成
「黑箱」的部分。

### 4.5 左栏导航

```
┌─────────────────┐
│ ⌕ 搜索           │   搜索会话 / 记忆 / 日志
│ ▾ 会话           │   会话列表，当前会话高亮，右键：重命名 / 导出 / 删除
│ ▾ 记忆           │   项目记忆 + 候选区（待整理的条目）
│ ▸ 工具           │   经 Tools.Enabled 过滤后的可调用集合 + 权限标注
│ ▸ 扩展           │   已加载扩展、来源、能力声明
│ ▸ 供应商         │   供应商 / 模型 / 连接测试（不含密钥明文）
│ ▸ 日志           │   实时日志（级别过滤），排错用
│ ⚙ 设置           │   主题、字号、快捷键、记忆策略、默认模型
└─────────────────┘
```

**折叠必须能用鼠标完成**：左/右栏各有一条 **28px 常驻窄条**与其中的切换按钮。
不把整列藏没的理由很直接——只留快捷键的话，鼠标用户一旦折叠就**没有任何办法展开**。
按钮提示写明动作（「折叠左栏」/「展开左栏」），而不是只给一个含义不明的箭头。
菜单（视图）、快捷键（`Ctrl+B` / `Ctrl+J`）、窄条按钮三条路径最终走同一个状态机，
不存在「菜单能展开、按钮不能」的分叉；折叠状态还有单元测试钉住往返
（见 `DesktopDesign.md` 第 8 节与 `TODO.md` `D-12`）。

**记忆分组是刻意的**：项目记忆是「已确认可用」的，候选区是「模型认为值得记、但还没被检验」的。
两者混在一起会诱导用户把未检验的内容当结论用 —— 与
[MemoryStorageDesign.md](MemoryStorageDesign.md) 的「先记录存档，后利用」一致。

**工具面板要显示权限标注**（`READ` / `WRITE` / `EXECUTE` / `ADMIN`），
让用户事先知道哪些操作会被拦下来。

### 4.6 底部状态栏

```
● 已连接  glm-4-plus   项目记忆: 已启用   上下文 12.4k / 128k   [Esc] 中断    v0.2.0
```

| 段 | 内容 |
|---|---|
| 连接 | 绿点=就绪 / 黄点=生成中 / 红点=错误 / 灰点=离线 |

## 6. 关键交互流程

### 6.1 一次带工具授权的问答

```
用户输入 → Enter
   │
   ├─ 消息入流（用户消息立即上屏）
   ├─ 状态：黄点「生成中」，输入框仍可用（可提前打下一句）
   │
   ├─ 助手流式输出 ────────→ 逐段上屏，Markdown 即时渲染
   │
   ├─ 工具调用 X（需授权）
   │     ├─ 卡片出现（灰色「等待授权」）
   │     ├─ 弹窗：工具 / 权限 / 参数 / 差异预览
   │     │     ├─ 拒绝 → 卡片转「已拒绝」，模型收到「未获授权」并继续
   │     │     ├─ 本次允许 → 执行
   │     │     └─ 本会话内始终允许 → 执行 + 记入 工具菜单
   │     └─ 执行中：卡片显示进度（执行类工具可能有实时输出）
   │
   ├─ 卡片转「完成」/「失败」，结果行给出耗时与规模
   ├─ 助手继续输出（可能再次调用工具，回到上一步）
   │
   └─ 本轮结束：绿点「就绪」，右栏刷新用量 / 工具 / 记忆命中
```

**注意「输入框仍可用」**：这是 CLI 端花了最大力气做成的能力，
桌面端天然具备（不同线程），不应退化为「生成期间锁死输入」。

### 6.2 中断

| 场景 | 行为 |
|---|---|
| 生成中按 `Esc` | 停止本轮；**已生成的部分保留在会话里** |
| 工具正在执行 | 请求取消；不支持取消的工具等它结束（界面提示「正在结束…」） |
| 工具等待授权 | 等同「拒绝」 |

### 6.3 查看与整理记忆

```
左栏「记忆」
   ├─ 项目记忆（已确认）—— 可编辑、可删除
   └─ 候选区（待整理）
         ├─ 逐条：采纳 / 编辑后采纳 / 丢弃
         └─ 「全部采纳」需二次确认（未检验的内容一次性进长期记忆风险大）
```

右栏「记忆命中」显示本轮召回了哪些条目，点击跳转到左栏对应项 ——
**让召回可见**是判断「记忆有没有用」的前提。

## 7. 状态设计

| 状态 | 表现 |
|---|---|
| **空会话** | 居中提示 + 三个示例任务（点击即填充输入框），不做纯空白 |
| **首字等待** | 助手处显示三个跳动点 + 底部黄点；**不显示假进度条** |
| **流式输出** | 光标跟随；代码块随分栏到达即时高亮 |
| **工具执行中** | 卡片显示旋转图标 + 已耗时（执行类显示实时输出尾部） |
| **等待授权** | 卡片置灰 + 弹窗模态 |
| **上下文接近上限** | 底部上下文段变黄 + 提示「按 Ctrl+K 压缩」 |
| **错误** | 内联错误条（可展开看详情），不是模态弹窗 —— 模态会打断阅读 |
| **连接失败** | 底部红点 + 内联提示 + 「重试」；已输入内容**不丢** |
| **无工具 / 无扩展** | 面板内给空态与「如何启用」的指引，不是空白列表 |

## 8. 架构与数据流

### 8.1 推荐方案：进程内直调（JavaFX 原生控件）

```
┌──────────────────────── AHA Desktop 进程 ────────────────────────┐
│                                                                  │
│   JavaFX UI 层（FXML + Controller）                              │
│         │                                                        │
│         │  调用（同进程、直接方法调用）                            │
│         ▼                                                        │
│   aha-core  AgentService ── AgentEngine ── 工具 / 记忆 / 安全     │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

- **UI 与引擎同进程**：`AgentService.streamChat(...)` 的 `AgentEventListener` 直接回调到 UI 线程
  （经 `Platform.runLater`）
- **无本地 HTTP 层**：不需要端口、不需要令牌、不需要处理端口占用与防火墙提示
- **依赖面小**：`aha-desktop` 只 require `aha-core` + JavaFX

### 8.2 备选方案：本地 HTTP + WebView

```
WebView（HTML/CSS/JS） ──HTTP/SSE──▶ 进程内 HTTP 服务器 ──▶ AgentService
```

- **收益**：顺带把 1.0 的远程接入协议提前跑通；UI 表现力（动画、Markdown、图表）最强
- **代价**：多一层协议与安全边界；WebKit 运行时体积大（分发包因此显著变大，
  且 WebKit 的签名 / 公证在各平台都有额外负担）；调试要跨越 Java / JS 两侧

### 8.3 结论（已决策，2026-10-08）

**0.2 采用 8.1（进程内直调 + JavaFX 原生控件）；8.2 仅作为兜底**——
只有当 8.1 无法满足需求时才启用。理由：

1. 0.2 的目标是「有可用的桌面端」，不是「验证远程协议」—— 后者有自己的版本规划
2. WebKit 运行时会让分发包体积显著变大，而 0.2 才刚开始分平台构建
3. UI 需要的能力（Markdown、卡片、折叠、异步流）JavaFX 原生控件都能覆盖，
   不必为此引入整个 Web 运行时
4. 进程内直调让「流式回调 → UI」的时序最简单，无需处理 SSE 断线重连

**已同步（2026-10-08）**：`DesktopDesign.md` §2/§3 已按本结论修订，并记录目标平台决策
（Windows + Linux 为支持承诺，macOS 只打包不测）。剩余待补的是**线程模型小节**
（单一桥接点、`runLater` 节流、取消与关窗联动、虚拟线程禁直触 FX 线程），见 `TODO.md` `D-07`。
