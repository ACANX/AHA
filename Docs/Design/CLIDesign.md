## 1. 技术

picocli + JLine（`picocli-shell-jline3`）。

## 2. 命令结构

```
aha
├── （无参数）                  交互式终端下等价于 `aha chat`；非交互环境打印帮助
├── init                      初始化配置（生成 Model.yml 与目录结构）
│   ├── --provider <id>
│   ├── --api-key <key>
│   ├── --no-input
│   └── --force
├── chat                      启动交互式对话
│   ├── --provider <id>
│   ├── --model <name>
│   └── --session <id>
├── run <input>               单次推理
├── tool                      工具管理
│   ├── list
│   └── invoke <name>
├── provider                  供应商管理
│   ├── list
│   └── test <id>
├── extension                    扩展管理
│   ├── list
│   ├── enable <id>
│   ├── disable <id>
│   └── info <id>
├── config                    配置管理
│   ├── get <key>
│   ├── set <key> <value>
│   └── edit
└── version                   版本信息
```

## 3. 主类

`com.acanx.module.aha.cli.AhaCli`，命令名 `aha`。

## 4. 启动脚本

`bin/Aha.sh`、`bin/Aha.bat` 通过 `--module-path` 加载模块。

### 5.1 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 参数错误、权限拒绝、供应商/工具不存在、推理失败 |

### 5.2 配置发现

`CliContext` 采用双文件配置：

| 文件 | 位置 | 缺省回退 |
|---|---|---|
| 主配置 | `./Aha.yaml` | classpath `AhaDefault.yaml` |
| 模型配置 | `Llm.ModelFile`（默认 '${AHA_HOME:-~/.aha}/Model.yml'） | classpath `ModelDefault.yml` |

`provider use/add/remove` 写回 `Model.yml` 后调用 `CliContext.invalidate()`，
使主配置与 Agent 服务缓存失效。配置与 Agent 服务均为懒加载单例，`shutdown()` 时释放。

## 6. 会话内命令（斜杠命令）

`chat` 的输入循环先做前缀分派：以 `/` 开头、且命令名只由字母 / 数字 / 连字符组成时，
交给 `SessionCommandRegistry`；否则作为普通消息发给模型。

| 命令 | 说明 | 状态 |
|---|---|---|
| `/help` | 列出可用命令 | ✅ |
| `/config` | 查看当前生效配置与来源 | ✅ |
| `/context` | 查看本轮上下文（消息数、Token 估算、模型、工具） | ✅ |
| `/session` | 查看会话 ID、固化身份、存储位置与续接方式 | ✅ |
| `/model [名称]` | 查看或切换本会话模型 | ✅ |
| `/clear` | 清空本会话上下文（保留会话与身份） | ✅ |
| `/tool [名称]` | 查看工具列表，或某个工具的权限与参数 | ✅ |
| `/compact [保留条数]` | 压缩上下文：用模型摘要替换较早的对话 | ✅ |
| `/autocompact [阈值\|off]` | 设置自动压缩阈值（如 `285k`、`1M`） | ✅ |
| `/memory [子命令]` | 查看 / 编辑 Agent 身份文件（用户级 `AHA.md` / 项目级 `AGENTS.md`） | ✅ |
| `/memory <子命令> [key]` | 记忆条目：列表 / 查看 / 写入 / 删除 / 检索 / 整理 | ⛔ 0.6 |
| `/stats` | 本会话用量统计（轮次、真实 Token、工具调用） | ⛔ 0.6 |
| `/exit` | 结束会话（同 `exit` / `quit`） | ✅ |

**`/memory` 的写入目标**：

| 目标 | 触发 | 说明 |
|---|---|---|
| 用户级（**默认**） | 无参数 | `$AHA_HOME` 或 `~/.aha` 下的 `AHA.md`，不存在则新建 |
| 项目级 | `--project` | 项目根下已有的身份文件；没有则建 `AGENTS.md` |
| 指定路径 | `--file <路径>` | 完全显式 |
| 指定文件名 | `--name AHA.md` \| `--name AGENTS.md` | 与上面两个叠加使用 |

默认用户级是刻意的：会话里的临时追加多半是个人偏好，**写进项目的 `AGENTS.md` 会被提交、
影响所有协作者**。

启动 `aha chat` 时会确保用户级身份文件存在（不存在则按骨架创建），因此
「默认写用户级」有确定的落点；只在用户级目录创建，**不碰项目目录**。

**来源要列全，不能只报优先级最高那份**：叠加生效时若只显示项目级，用户会以为自己的
全局记忆根本没生效。因此 `SystemPromptLoader` 在多份命中时用 `files:<用户级>;<项目级>`
形式给出全部来源，`/memory view` 也按文件分节展示、全局在前。

**命令边界（刻意划清，避免用户误判作用范围）**：

| 命令 | 边界 |
|---|---|
| `/config` vs `aha config get` | 前者看**本会话**的全部有效配置与来源，后者查**进程级**单个键。二者共用取值逻辑（`ConfigView`），但不共用解析器 |
| `/context` vs `/session` | 前者答「这一轮带什么上下文发给模型」，后者答「这条会话记录存在哪里、怎么续接」 |
| `/model` | **只改模型，不改供应商**：会话配置里固化的只有模型名，供应商由 `Model.yml` 的 `Default` 决定（进程级）。传供应商 ID 会提示改用 `aha provider use <id>` |
| `/clear` | 只删**历史消息**；会话记录、系统提示词、模型均保留（清空后仍是同一个会话），长期记忆也不受影响 |
| `/tool` | 列的是**实际可被模型调用**的集合（经 `Tools.Enabled` 过滤），而不是注册表里的全部工具 |
| `/compact` vs `/autocompact` | 前者是「现在就压」，后者是「超过多少就自己压」。自动压缩只是**复用** `/compact` 命令，不另写一套逻辑 |
| `/autocompact` 阈值 | 固化在会话配置的 `Extras` 里，因此 `aha chat --session <id>` 续接后设置仍在；`off` 直接移除键而非写 0 |
| `/memory` 的两层含义 | 0.1 起 `/memory` 指**身份文件**（用户级 / 项目级 Markdown，启动时读入，每个来源各自作为一条 system 消息注入）；0.6 起的**记忆条目**（`memory` 表）作为同一命令的子命令，不再另起命令名 |
| `/memory` vs 长期记忆条目 | 身份文件是**人写的指令**，记忆条目是**系统存的条目**，二者载体与用途都不同；前者直接影响 system 消息，后者需检索后注入 |
| `/memory` vs `/context` | 上下文历史（`message` 表）由 `/clear` 与 `/compact` 管理；`/memory` 动的是跨会话的身份与长期内容 |
| `/memory` vs `/config` | 前者编辑的是**身份文件**，后者只是展示配置中与身份文件相关的键；改文件本身不是改配置 |

**设计要点**：

- **与进程级命令分离**：`/config` 不是 `aha config` 的别名。前者作用于**会话生命周期内**的
  状态（会话已固化的模型、系统提示词、当前上下文），后者作用于**进程级配置**。
  二者共用取值逻辑（`ConfigView`），但**不共用解析器**（picocli 不参与会话内命令）
- **未知命令不发给模型**：`/xxx` 未注册时提示错误并列出可用命令，
  否则用户会以为指令已生效
- **路径不误判**：`/usr/bin/ls` 的命令名后跟 `/`，按普通消息处理
- **注册表为扩展预留**：0.1 只注册内置命令；0.3 起扩展点 `CommandProvider` 注册的命令
  并入同一注册表，使 CLI 与未来其他前端共用同一命令面

**`/context` 的数值口径**：

| 项 | 来源 |
|---|---|
| 模型 | 会话固化的 `SessionConfig.model`，为空时回退运行时默认值 |
| 历史 | `loadHistory` 实际加载条数；与存储总量的差值说明窗口截断或不完整消息 |
| Token | 手算估算（CJK 按 1 字 ≈ 1 token，其余 4 字符 ≈ 1 token），**不引入 tokenizer 依赖** |

三项共用 `ContextSnapshot` 与 `TokenEstimator`，而不是各写一份。否则「自动压缩怎么没触发」
会因三处算法不同而无从判断。

**上下文压缩（`/compact`）**：

- 把较早的对话交给模型摘要，再用摘要替换那批消息，只保留最近若干条
  （默认 `ContextCompactor.DEFAULT_KEEP_MESSAGES = 10`，`/compact N` 可指定）
- **不可逆**，因此守两条底线：摘要生成失败或返回为空时**绝不**改动历史
- 摘要以 `system` 角色写回。三个适配器都会把 `system` 消息提到顶层系统提示词，
  因此摘要天然位于保留消息之前，不依赖位置技巧
- **不切开工具调用组**：若切割点落在 `tool` 消息上就继续前移，否则会构造出
  以 `tool` 消息开头的历史，服务端直接拒绝
- 价值不只是省 token：会话一旦超出上下文窗口，最早的历史本来就会被丢弃，
  压缩是把「静默丢弃」换成「有损但留痕」

## 7. 终端与渲染决策

> **当前实现形态见 [TUIDesign.md](TUIDesign.md)**：本节记录决策过程与备选方案，版面、样式示例、降级矩阵与实现机制集中在 TUIDesign.md，改代码前先看那份。

**形态：内联 REPL（inline），不做全屏 TUI。**

对标 pi / claude code：不接管屏幕，保留终端**原生 scrollback**、搜索、复制粘贴、
`| less`、重定向落盘。全屏 TUI（alternate screen）会吃掉 scrollback，且在 Windows
conhost 上最不稳，对「长输出、需回看」的 coding agent 是负优化。

**模块边界：不新增 `aha-tui` 模块。**

终端差异由 JLine 的 `Terminal` 抽象承担，无需为 CMD / PowerShell / Windows Terminal /
WSL / Linux 各写适配器；`aha-desktop`（0.2）走 JavaFX，不会复用 ANSI 渲染器，
真正共享的只有 `AgentEvent` 契约（已在 `aha-common`）。因此新增模块只会得到唯一消费者。
渲染层先在 `aha-cli` 内部按包分层（`session/`，后续 `render/`、`tty/`），
待出现第二种 ANSI 消费者时再提取为模块。

**兼容策略：探测能力，不探测平台。**

| 环境 | 处理 |
|---|---|
| Windows Terminal / 终端预览版 | 一等公民，无需特殊处理 |
| Windows CMD（conhost） | 由 JLine 开启 VT 处理；避免依赖光标精确定位的渲染 |
| PowerShell 5.1 | 输出编码随代码页（中文环境 936），需处理 `Console.OutputEncoding` / 代码页 |
| WSL | 宿主为 Windows Terminal 时经 ConPTY，能力完整 |
| Linux terminal | 一等公民 |

需探测的**能力**（而非平台名）：

- 是否 TTY —— 管道 / CI 下降级为纯文本，否则会输出 ANSI 转义垃圾
- `NO_COLOR` / `--no-color`（业界约定）
- 宽度 —— 折行必须按**显示宽度**而非 `String.length()`，否则中文与 emoji 必错行
- 色彩深度 —— `COLORTERM` 真彩 / 256 / 16

**已实现（0.1）**：

| 件 | 职责 |
|---|---|
| `tty/TerminalCapabilities` | 能力探测：TTY / 色彩深度 / 宽度，输出日志供排查 |
| `render/TextWidth` | 显示宽度（East Asian Width 子集）：折行与对齐的唯一依据 |
| `render/LineWrapper` | 按显示宽度折行，**跨流式分片**记住列号 |
| `render/Style` | 着色词汇（只用基础 SGR） |
| `render/MarkdownStream` | 流式 Markdown 轻量渲染（标题 / 列表 / 围栏代码 / 行内代码 / 粗体 / 斜体） |
| `render/InlineScanner` | 行内构造扫描：定界符歧义判定（侧翼规则）与嵌套递归 |
| `render/StreamRenderer` | 内联渲染：正文流式输出、工具调用 / 结果 / 错误 / 用量成块输出、长结果截断 |
| `render/StatusLine` | 瞬时状态行：等待期间的转圈动画、阶段、耗时、模型与累计用量 |
| `render/Renderers` | 按能力选样式（带色 / 纯文本） |
| `tty/OutputEncoding` | 输出编码探测与符号降级（`❯` / `✓` 在 GBK 下不可表示） |

`--no-color` 与 `NO_COLOR` 环境变量都会关闭颜色；输出被重定向时自动降级为纯文本
（不输出 ANSI，也不插入硬换行）。

**控制台编码**：探测 `Console.charset()` / `stdout.encoding`，用 `Charset.newEncoder()`
`canEncode(...)` **实测**能否表示 CJK 与装饰符号，不值则降级符号（`❯ ` → `> `、`✓` → `[ok]`），
完全不能表示中文时用 **ASCII** 提示用户切换控制台编码（提示本身也要能读）。
刻意不在启动脚本里自动 `chcp 65001`：PowerShell 5.1 会缓存 `[Console]::OutputEncoding`，
子进程改代码页后它仍按旧编码解码，反而更乱。

**包分层**：`session/`（会话内命令）、`render/`（渲染）、`tty/`（终端探测），
均在 `aha-cli` 内且不导出；待出现第二种 ANSI 消费者时再提取为模块。

**Markdown 渲染**：处理标题、列表、围栏代码、行内代码、粗体 / 斜体。

关键约束是**不牺牲流式**：块级构造只取决于行首最多 8 个字符（`#`、`- `、`1. `、`> `、
三个反引号的围栏标记），因此只缓冲这么长即可判定；行内代码与强调是跨片构造，缓冲上限 200 字符，
超出即按纯文本吐出（否则一个未闭合的定界符会把后续内容一直扣住）。**围栏代码内部原样输出**——
代码里的 `#`、反引号、`-`、`*` 都不应被当成 Markdown，否则读者会被错误高亮误导。

**强调的歧义判定**（`InlineScanner`）采用 CommonMark 的侧翼思路做一个可解释子集：

| 定界符 | 开定界符要求 | 闭定界符要求 |
|---|---|---|
| `*` | 后一个字符非空白 | 前一个字符非空白 |
| `_` | 后一个字符非空白，且**前一个字符非字母数字** | 前一个字符非空白，且**后一个字符非字母数字** |

这样才能避免 `2 * 3 * 4` 被误判为斜体、`a_b_c` 被误判为强调。`*` / `_` 连用
1 / 2 / 3 个分别表示斜体 / 粗体 / 粗斜体；4 个及以上按字面量输出。
刻意不做删除线（`~~`）：它需要 SGR 9，支持面比加粗 / 斜体窄得多。

> 正文按**每段增量**即吐出，不按长度攒批：攒批会让流式变成一批一批到达，延迟可感。

**等待反馈**：`StreamRenderer` 在「等待中」显示瞬时状态行（首次响应前、工具执行期间），
写正文前立即清除。它只依赖 `\r` 重绘，不用光标定位 / 清屏序列；非 TTY 或宽度未知时自动关闭。
要让状态行与流式正文**同时**显示，需要底部保留区，属另一项工作。

**流式期间保持输入可用（0.1 已实现）**：模型还在输出时，用户仍可敲下一条消息，
也可 Ctrl+C 打断本轮。

形态：

- **主线程常驻 `readLine`**；回合跑在单线程虚拟线程执行器上，期间的输入排队、回合结束后依次处理
- 回合输出经 `AboveStream`（行缓冲）→ `LineReader.printAbove` 打到输入行**上方**，
  输入行始终留在底部、始终可编辑
- `Ctrl+C` 由 JLine 在主线程抛出 `UserInterruptException` → 取消当前回合的
  `CancellationToken`（已生成的部分仍会落库）；空闲时只清空输入行
  （此前会直接退出整个会话，与 shell 惯例不符）
- 该模式下**关闭瞬时状态行**：`printAbove` 之下输出不再处于行首，
  原地 `\r` 重绘只会变成污染输出的碎片
- 工具授权的问答走队列：授权发生在回合线程上，而 reader 由主线程持有，
  回合线程直接读会争用同一把读锁

两条踩过的坑（均为实测结论，不要重试反方向）：

1. **`readLine` 必须由主线程调用。** 把输入放到后台读线程后，JLine 的 SIGINT 处理会失效——
   Ctrl+C 按默认行为直接结束 JVM，整个会话被杀，而不是「打断当前生成」
2. **模块路径下必须 `requires jdk.unsupported`。** JLine 用反射调 `sun.misc.Signal` 处理 Ctrl+C，
   而 `sun.misc` 只由 `jdk.unsupported` 导出；不声明就找不到，同样是 Ctrl+C 杀进程。
   独立探针跑在 classpath（无名模块）上能读所有 JDK 模块，因此这个问题只在模块路径下暴露

### 7.2 输入行构成

输入行由**上下两条分隔线**框住，且**不加 `> ` 之类的提示标记**——线本身已经说明这里可以输入，
再加符号只是噪音：

```
（正文区，流式输出往下走）
──────────────────────────────  ← 上分隔线：由 LineReader 的 prompt 给出
（这里是输入行，光标从行首开始）
──────────────────────────────  ← 下分隔线：由 Status 的边框给出
⠋ 等待响应… 1.2s  deepseek-chat · 512 tok
```

因此**状态行不能真正“隐藏”**：底部那一行兼着输入行下边框的职责，回合结束就撤掉的话，
输入区会突然失去框线。所以 `StatusLine` 的收尾动作是 `idle()`——把内容换成空闲文案
（显示模型名），而不是 `hide()`。

分隔线宽度取 `width - 1`：满宽会触发终端自动换行，把一条线挤成两行。

> **为什么状态行在输入行下方，而不是上方**（已两次尝试并否决）：
> JLine 的 `org.jline.utils.Status` 只能占底部保留区，输入行必然在它上方。
> 要把状态行放到输入行**上方**，只能把它作为多行提示符的一部分，靠
> `LineReaderImpl.setPrompt + redisplay` 刷新。探针里它确实能显示、也能刷新，但与流式正文经
> `printAbove` 上抛**互相冲突**：正文会整段消失，且因为 `PrintStream` 吞掉异常而**没有任何报错**。
>
> 第二次尝试加了「有正文在流时不重绘」这个不变量，仍然失败（两次实测分别只显示 6/12、3/12 行）。
> 这说明问题不是刷新时机，而是 `printAbove` 与提示符重绘**共享同一套显示状态**，
> 重绘几次之后 `printAbove` 就写偏了。
>
> 结构上的结论：**能原地重绘的位置只能在输入行下方**——JLine 的行读取器必然把输入行放在内容区底部，
> 可控的只有「输入行上方（提示符，静态）」与「输入行下方（`Status`，可重绘）」。
> pi 能做到是因为它自己接管整块底部渲染（全屏 TUI），不依赖行读取器。

### 7.3 工具区块

一次工具调用展开为**带背景色带的区块**：

```
（空行）
 读取  file-read  src/main/Foo.java       ← 类型色带（整行铺底）
 ✓ 完成 · 0.8s · 42 行                     ← 结果色带（成功中性 / 失败红）
   （输出前 3 行，弱化缩进）
   … 还有 39 行
```

要点：

- **按操作的后果分类着色**，而不是给每个工具一个颜色：读取（查看，安全）、写入（改数据）、
  执行（跑命令）、网络（发请求）四类的后果完全不同，颜色承担“刚才发生了什么”的区分
- 配色分两档：256 色 / 真彩用暗灰底（`48;5;236`）+ 类型色标签，长时间阅读不刺眼；
  16 色用亮底 + **显式前景色**——16 色下亮底配默认前景在浅色终端上几乎不可读
- 无色时退化为结构标记（`[读取] file-read  path`），不能因为没颜色就丢掉可辨识性
- **色带必须自己铺满整行**：只给颜色不铺底，看起来是一段彩色文字而不是“区块”；
  铺底要按**显示宽度**计算，且截断必须发生在上色之前（否则 `TextWidth` 会把 SGR 序列当字符数）
- 工具输出只给**前 3 行 + 「还有 N 行」**：全量贴进对话只会淹没上下文，
  需要细节时模型自己会再看一遍
- `ToolResultEvent` 新增 `success` 字段：展示层要按成败着色，而从 `"ERROR: "` 前缀反推
  既脆弱又会被工具文案改动破坏。事件携带的是**给人看**的结果（失败为错误信息本身），
  回灌给模型的消息仍保留 `ERROR:` 前缀

### 7.1 常驻状态行（0.1 已实现）

「流式期间保持输入可用」落地后，状态行从「瞬时、只用 `\r` 重绘」变成了新问题：
`printAbove` 之下输出不再处于行首，原地重绘无从谈起。0.1 的结论是**用 JLine
`org.jline.utils.Status` 在终端底部保留一行**，而不是把状态混进输出流。

选型时的取舍（已决定接受代价）：

| 方案 | 取舍 |
|---|---|
| **A. `Status` 底部常驻行（已采用）** | 依赖滚动区域 + 光标定位，偏离「不碰光标控制序列」；改变原生滚动与复制行为；换来可持续刷新的耗时与用量 |
| B. `printAbove` 阶段性一行 | 不打乱终端行为，但一锤定音，无法显示耗时与用量 |
| C. 不显示 | 等待首次响应与工具执行这两个无输出阶段完全没有反馈 |

**实现**（`cli/tty/StatusSurface` + `JLineStatusSurface`）：

- `StatusSurface` 抽象出「可原地重绘的一行」；空实现 `NONE` 负责降级
- **按能力门禁，而不是「创建成功即可用」**：`Status.getStatus()` 在 dumb 终端上照样返回对象，
  但它占不住底部区域，`close()` 还会 NPE（JLine 自身问题）。因此要求三者同时成立：
  类型非 `dumb`、`change_scroll_region` 能力存在、行数 > 0
- JLine 不处理窗口变化 → 每次刷新前比对尺寸并调用 `resize()`
- 状态行走**独立通道，不写输出流**：否则会与正文错行，还会进管道与日志
- 终端让位（`/memory edit`）前先 `hide()`，否则编辑器的画面会被切碎
- 文案仍由 `StatusLine` 组装，但**只有转圈帧与当前阶段**：状态行只回答「它现在在干什么」。
  耗时与规模属于「这一次操作」的信息，由工具区块的末行承担（见 7.3）；模型名与用量不再挤在这一行

**实测**（伪终端 + 慢速 SSE mock）：

```
滚动区域设置与复位        ✓
状态区出现「等待响应… 12.3s  mock-model」  ✓
转圈帧出现 4 种：⠋ ⠙ ⠹ ⠸   ✓ ← 原地重绘，不是逐行上抛
流式输入 / Ctrl+C 中断     未受影响 ✓
```

> 伪终端下**必须设置窗口尺寸**（`TIOCSWINSZ`），否则 JLine 看到 0×0、
> `Status` 算不出滚动区域而完全不显示——这不是缺陷，是降级路径。
