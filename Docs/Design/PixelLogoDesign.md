## 1. 目标与不做什么

| 目标 | 说明 |
|---|---|
| 一眼认出是 AHA | 与 `Logo.svg` 同构：9 条光线 + 灯泡 + 字样 + 笑脸 + 灯座 |
| 像素块可数 | 粗格、硬边界、平色——不是"低分辨率缩略图" |
| 任何代码页都能显示形状 | 形状只依赖 `▀`；颜色可降级 |
| 能复现 | 生成器入库，常量可校验，漂移会被测出来 |
| 不干扰对话 | 透明处走终端默认色，不铺底卡 |

**不做**：任意尺寸缩放（只有 48 与 24 两档）、图片文件渲染、鼠标/超链接交互。

## 2. 原型：`Logo.svg` 的构成

标志是 `Logo.svg` 的像素重画，元素一一对应：

| 元素 | `Logo.svg` 中的位置 | 像素画中的画法 |
|---|---|---|
| 9 条光线 | 9 个 `<line>`，围绕中心呈放射状 | 1 像素宽直线（Bresenham） |
| 灯泡 | 贝塞尔封闭路径，包围盒约 262x270 | 整数圆 + 1 像素轮廓 |
| `AHA` 字样 | 灯泡内上部（`y≈230`，字号 64） | 5x7 点阵直接贴 |
| 笑脸 | 眉毛、眼睛、微笑（`y≈256~370`） | 3x3 眼睛 + 眉毛 + 13 像素微笑 |
| 灯座 | 梯形 + 5 条螺纹线 | 向下收窄梯形 + 交替双色螺纹 + 底盖 |

光线的 9 个方向（角度制，逆时针为正，`90` 为顶端）：

| 角度 | 归属 |
|---|---|
| 90 |
| 61 |
| 32 |
| 0 |
| -32 |
| 148 |
| 119 |
| 180 |
| 212 |

即「顶部 1 条 + 两侧各 4 条」，与 `Logo.svg` 一致——早期只画了 3 条，是被明确纠正过的错误。

## 3. 为什么是像素风，以及为什么不能"采样"

**像素画是摆出来的，不是缩采样出来的。** 把 `Logo.svg` 低分辨率采样会同时坏掉三件事：

| 采样会坏掉 | 后果 |
|---|---|
| `AHA` 点阵 | 5x7 的点阵被平均成灰糊，读不出字 |
| 1 像素宽的光线 | 被抹平或打成虚线，只剩光秃秃的灯泡 |
| 边界 | 出现半透明像素（抗锯齿），失去像素块的可数性 |

因此像素风遵守三条规则：

1. **按格摆**：所有图元都落在整数格上，先算形状再落笔
2. **硬边界**：不做抗锯齿、不做超采样平均
3. **平色**：颜色收敛到固定调色板，不做位置渐变

> **反面教材**：曾有一版用 24x26 细网格 + 超采样平均 + 位置渐变实现，
> 结果是"既不像 ASCII、也不像像素画"的模糊缩略图，被否决。教训是：
> 像素风格的关键不是"分辨率低"，而是**像素块一眼可数**。

## 4. 画法

### 4.1 画布与像素形状

| 项 | 取值 | 说明 |
|---|---|---|
| 画布 | 48x48 像素 | 见 §1 的尺寸取舍 |
| 字符格 | 半块 `▀`，前景画上半格、背景画下半格 | 一个字符格承担 2 个像素 |
| 显示尺寸 | 48 列 x 24 行 | 终端字符格高宽比约 2:1，故落成正方形 |
| 实心像素数 | 48x48 档 815 个 / 24x24 档 240 个 | 其余为透明 |

### 4.2 图元

| 元素 | 画法 | 关键点 |
|---|---|---|
| 光线 | 沿角度取内外两个端点，走 Bresenham | **不能**按半径逐步取整：会在同一列上重叠，画出虚线 |
| 灯泡 | 以 `(23.5, 24.0)` 为心、`R=13.5` 的整数圆 | 轮廓 1 像素；内部上下两段平色（不是渐变） |
| `AHA` | 5x7 点阵（`A` / `H`），整体水平居中后**覆盖**写入 | 只写 `1` 的格子，字腔保留灯泡色 |
| 笑脸 | 眼睛 3x3、眉毛 4 像素、微笑 13 像素 | 全部贴在灯泡内部 |
| 灯座 | 梯形（`half = 9.5 - i*0.28`）+ 螺纹 + 底盖 | 顶宽必须小于灯泡底口，否则会"套不住" |

### 4.3 调色板

| 字符 | 语义 | RGB | 256 色号 |
|---|---|---|---|
| `a` | 灯泡轮廓 | `#B45309` | 172 |
| `b` | 灯泡下半 | `#F59E0B` | 214 |
| `c` | 灯泡上半 | `#FDE68A` | 229 |
| `e` | 光线 | `#FBBF24` | 221 |
| `g` | AHA 字样 | `#7C2D12` | 94 |
| `f` | 笑脸 | `#5B2107` | 94 |
| `l` | 灯座亮 | `#E5E7EB` | 195 |
| `n` | 灯座中 | `#9CA3AF` | 247 |
| `k` | 灯座暗 | `#4B5563` | 66 |

调色板是**平坦**的：没有中间过渡色，没有位置渐变。灯泡的立体感只靠"上半亮、下半主色"两段，
外加 1 像素轮廓。`Logo.svg` 里的渐变与高光在 48x48 下会退化成噪点，故不保留。

颜色换算走 xterm-256 立方体（灰阶走 232~255 段），与 `StartupPixelLogo#color` 一致。

### 4.4 两档尺寸与降采样

| 档位 | 尺寸 | 来源 | 用途 |
|---|---|---|---|
| 完整 | 48x48 | 直接绘制 | 宽终端（≥109 列） |
| 降采样 | 24x24 | 完整档按 2:1 降采样 | 窄终端（≥85 列） |

降采样规则：每个 2x2 块内**多数非透明像素胜出**，全透明则为透明。

**平票必须按固定优先级裁决**（`e → g → f → a → c → b → l → n → k`）。
不能让 `set` 的迭代顺序决定：Python 字符串哈希默认随机化，同一份输入**跨进程**会得到不同网格，
生成器与 Java 常量就会莫名其妙地对不上。

## 5. 渲染

| 项 | 规则 | 原因 |
|---|---|---|
| 编码 | 前景 = 上像素，背景 = 下像素，字符恒为 `▀` | 一个字符格表达两个像素 |
| 透明 | 走终端默认色 `39` / `49` | 不画底卡、不压暗终端背景；深色背景下不会出现突兀黑框 |
| 不着色 | **不显示标志** | 像素风靠颜色成形，无色的半块字符只是乱码般的色块 |
| 行尾 | 不补空白 | 右对齐由组装层负责；尾部留白会让重定向输出变脏 |
| 宽度 | 着色一次完成，之后**不再测量** | SGR 序列会被当成普通字符，测出来的宽度是错的（与 `ToolBlock` 同一条约束） |

## 6. 与终端能力的配合

`aha chat --logo auto|pixel|ascii|off`（默认 `auto`）：

| 取值 | 行为 |
|---|---|
| `auto` | 支持 `▀` 且着色 → 像素风；否则线框风 |
| `pixel` | 强制像素风；终端不支持时不显示标志 |
| `ascii` | 强制线框风 |
| `off` | 不显示标志 |

候选顺序（取第一个放得下的）：`48x48 → 24x24 → 线框完整 → 线框紧凑`。

之所以把像素风挂在能力门禁之后：它在 GBK 等非 UTF-8 代码页下会整片退化成 `?`，
而启动横幅是用户最先看到的东西——**烂成乱码比朴素更糟**。

## 7. 版面集成

- 标志与**顶栏**（标题、供应商、模型、端点、工作目录）并排
- 其余细节（项目根、身份来源与加载顺序、会话）在标志**下方整宽**打印
  ——它们带绝对路径，实测最宽 78 列，若一并并排会把标志挤出 80 列屏幕
- 右侧留 **4 列**空白：贴着终端右边缘观感局促，且满宽会触发终端自动换行

组装实现在 `StartupBanner#compose`，标志以 `LogoArt`（宽度 + 已着色行）传入，
因此像素风与线框风走同一条并排逻辑。

## 8. 复现

### 8.1 生成器

```bash
python3 bin/GenPixelLogo.py --art      # 打印 48x48 与 24x24 网格（肉眼校形）
python3 bin/GenPixelLogo.py --java     # 打印可粘贴回 Java 的数组字面量
python3 bin/GenPixelLogo.py --verify   # 校验 Java 常量与生成器一致
```

**Java 常量是构建的唯一来源**，不在构建期生成——`--verify` 只做漂移检测：
改了生成器的几何或调色板后没同步常量，它就会报出首个不同的行号。
建议在 CI 里跑一次 `--verify`。

### 8.2 改一版像素画的顺序

1. 改 `bin/GenPixelLogo.py`（图元坐标、角度、调色板）
2. `python3 bin/GenPixelLogo.py --art` 用眼睛确认形状
3. `python3 bin/GenPixelLogo.py --java`，把两个数组贴回 `StartupPixelLogo.java`
4. `python3 bin/GenPixelLogo.py --verify` 确认一致
5. 跑 `StartupPixelLogoTest`，并在伪终端里实跑一遍（见 8.3）

### 8.3 伪终端验证

像素风依赖真实宽度与颜色，**必须实跑**，不能只看单测：

| 项 | 要求 |
|---|---|
| 窗口尺寸 | 必须用 `ioctl(TIOCSWINSZ)` 设定，否则 JLine 拿到的是默认 80x24 |
| `TERM` | `xterm-256color` |
| 观察档位 | 宽屏应命中 48x48；收窄后逐档退到 24x24、线框完整、线框紧凑、无标志 |
| 非 TTY | 管道下必须**不出现任何转义序列**，也不显示标志 |

### 8.4 测试

| 测试 | 钉住什么 |
|---|---|
| `StartupPixelLogoTest#fullArtIsFortyEightByTwentyFour` | 完整档尺寸 |
| `StartupPixelLogoTest#smallArtIsHalfOfTheFullArt` | 降采样档尺寸恰为一半 |
| `StartupPixelLogoTest#everyLineFitsInsideTheDeclaredWidth` | 行宽不超宣告宽度 |
| `StartupPixelLogoTest#usesHalfBlocksAndTwentyFiveSixColors` | 只出现 `▀`；非空行必带 SGR |
| `StartupPixelLogoTest#transparentPixelsFallBackToTheTerminalDefaults` | 透明走 `39`/`49`，不是黑色 |
| `StartupPixelLogoTest#noLineCarriesTrailingWhitespace` | 行尾不留白 |
| `StartupPixelLogoTest#theNineRaysSurviveAsDistinctPixels` | 9 条光线没被抹平 |
| `StartupPixelLogoTest#theWordmarkAndFaceAreDrawnInsideTheBulb` | 字样与笑脸没被灯泡盖掉 |
| `StartupBannerTest` | 并排、降级、按显示宽度补位（中文标签） |
| `StartupLogoTest` | 线框风：纯 ASCII、宽度契约、四档配色 |

## 9. 已知限制

| 限制 | 说明 | 出路 |
|---|---|---|
| 依赖 `▀` 与 256 色 | 不支持时回退线框风或不出标志 | 见 §6 |
| 需要 85 列（完整档 109 列） | 更窄只有线框风或无标志 | 与顶栏宽度相关，顶栏越短门槛越低 |
| 16 色终端观感下降 | 琥珀金与灰阶被压扁成几种色 | 未单独调 16 色档；必要时按 `ColorDepth` 另配 |
| 不做任意缩放 | 只有 48 与 24 两档，非整数缩放会毁掉点阵 | 需要更大尺寸就改生成器并重出常量 |
| 图形不含环境信息 | 供应商/模型/端点仍在顶栏文字里 | 有意为之：图形只负责品牌识别 |
