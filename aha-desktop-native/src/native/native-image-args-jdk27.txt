# AHA 桌面端 · GraalVM native-image 参数清单（JDK 27 试验分支）
#
# 用法：由 POM 的 native-jdk27 profile 选择本文件：
#     ./mvnw -Pdesktop-native,native-jdk27 -pl aha-desktop-native,aha-desktop -am package -DskipTests
#
# ── 这一份与 JDK 25 那份的关系 ────────────────────────────────────────────────
# 基线（JDK 25）那份是**能编出来**的起点；这一份是**用来做对比实验**的。
# 因此这里的每条改动都要能回答一个问题：「它把启动时间或内存占用改了多少？」
# 改完把结果记到 Docs/Design/DesktopNativeDesign.md 第 5 节的对比表里。
#
# ── 关注点（对应「为 JDK 29 铺路」这件事）─────────────────────────────────────
# 1. Project Leyden：AOT 类装载与链接、AOT 方法剖析。
#    注意：native-image 本身已是「全量 AOT」，Leyden 的 AOT 缓存主要作用在 **JVM 模式**。
#    因此这里的对比实际上是「原生镜像（JDK25 编）vs 原生镜像（JDK27 编）vs JVM+AOT 缓存」，
#    第三条腿在 jar 模式下做（见 DesktopNativeDesign.md 第 5 节的三种形态）。
# 2. 原始类型（Valhalla，预览）：价值在于去掉装箱与指针追逐。它需要**源码**使用值类型，
#    光换 JDK 不会有效果——因此这一条目前只记录「是否可编译 / 预览开关是否与 native-image 兼容」。
# 3. GC 策略：native-image 侧默认是 serial；下面对比位列了 epsilon 与 G1。
#    取舍见下：epsilon 没有运行时回收，只适合「短命进程」，不适合本应用（一次会话可能很久）。
#
# ── 2026-10-08 同步 ──────────────────────────────────────────────────────────

# 输出改 -o、加 --emit build-report / --gc=G1 / --future-defaults=all / -R:MaxHeapSize）。
# 本文件**逐条同步**了这些改动，且**保持行序与基线完全一致**——
# 这样两份文件的 diff 就正好是「JDK 轴真正的差异」，不会混入无关顺序变化。
# 逐条的处置理由写在基线那份文件里，这里不重复。

# ── 实验结果位（默认注释掉：先跑「同参数 + 换 JDK」这条最干净的对比）──────────
#
# ① GC 选择（本应用是长驻 GUI，epsilon 只适合短命进程，仅作数据点）
#    --gc=epsilon      启动最快、内存最省，但**没有回收**：会话久了会 OOM
#    --gc=serial       默认；单线程 GC，停顿可预期
#    --gc=G1           并发回收，堆大时更稳，但启动与静态体积更大
#
# ② 镜像体积 / 启动的常见取舍位
#    -H:-IncludeAllTimeZones      只带上用到的时区（体积 -1~2 MB）
#    -H:-IncludeAllLocales        同上
#    -H:+UseCompressedReferences  32 位引用（默认在 <=32 GB 堆上开启）
#
# ③ 堆参数（基线已显式给 1g；这里可对比更小的上限）
#    -R:MaxHeapSize=512m
#    -R:MinHeapSize=64m
#
# ④ CPU 特性（对外分发的产物不要用 native）
#    -march=x86-64-v3
#
# ⑤ 手工 PGO（两阶段，先有典型负载样本）
#    --pgo=default.iprof
